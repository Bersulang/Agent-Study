## 1. 业务场景

工单助手最后回答“已创建”，不代表创建动作合规。它可能跳过审批，或者调用两次。需要把实际执行事件作为测试对象。

## 2. 学习目标与前置知识

先完成前面的 Python、工具、状态和协作基础。本课重点是理解机制，能够修改并验证代码。遇到不理解的语法先查看本课语法说明，再回到基础阶段复习。

学习完成后，能独立完成下方新需求，说明失败条件，并用测试检验结果。材料准备完毕不表示已经通过能力验收。

## 3. 关键概念

### 1. 轨迹与最终答案

轨迹按顺序记录任务实际事件，例如 started、approved、write、finished。文本回答与执行轨迹分开验证；回答相同不意味着行为相同。不要把模型隐藏推理当审计依据。

### 2. 时序不变量

不变量是所有合法执行都必须满足的规则，例如写入前有批准、写入至多一次、结束后无动作。检查器在遍历事件时维护状态，发现违规直接失败。

### 3. 测试层次与契约

单元测试验证一个检查器；契约测试验证工具参数和事件格式；集成测试验证审批与数据库；端到端测试验证完整任务。与 Java 单元、接口和集成测试分层类似，不能全部依靠最慢的端到端测试。

## 5. 代码执行过程与新语法

检查第一条是started；按事件更新批准和写入状态；write发生时同时检查授权、审批和是否重复；finished出现后禁止任何事件。最后要求有结束事件。

### 本课语法提示

`elif` 表示互斥的后续条件；集合用于允许值判断；异常类型区分权限失败和数据格式错误，测试使用 assertRaises 验证失败路径。

函数的参数表示需要提供的信息，返回值表示结果。异常表示当前调用不能继续，不能简单吞掉所有异常；需要将失败类别传给上层处理。注释与讲义共同解释关键决策。

## 6. 常见错误与排查

| 症状 | 原因 | 排查与修复 |
| --- | --- | --- |
| 答案正确但未审批 | 只评分最终文本 | 读取实际工具事件并检查时序 |
| 测试绑死每个模型步骤 | 断言不稳定的精确轨迹 | 检查业务不变量和允许的动作集合 |
| 重复写入没发现 | 只检查是否曾经成功 | 累计实际写入次数 |

排查时保留输入类别、状态与错误码；涉及身份、密钥和业务数据时，先脱敏再记录。一次运行成功只能证明当前案例，必须覆盖变化后的需求和失败路径。

## 源码分段追踪与Java对照

### 输入和初始化

事件列表记录可观察操作，不包含模型隐藏思维链。

第一个事件必须started；空轨迹或从write开始无法解释任务边界。

approved变量初始False，表示任务尚无可用业务批准。

writes是已观察业务写入次数，初始0，不是模型调用次数。

finished初始False，每个事件处理前都检查终态。

### 校验与状态推进

approved事件将批准状态改成True，但authorized仍需另行成立。

revoked将批准重置False，不删除历史批准事件。

write同时检查身份权限与当前批准，任意一个失败都会抛PermissionError。

写计数增加后超过1，说明同一逻辑操作重复，抛ValueError。

这只是轨迹审计规则，不会撤销已经发生的远程副作用。

read和planned是本课允许的无写入事件，不改变批准状态。

finished把终态设为True，后面的read也会被拒绝。

循环结束还未finished，说明轨迹不完整，不能按成功评价。

### 失败与验证证据

只读任务started/read/finished允许通过，writes返回0。

同样声称“任务完成”的两个结果，执行轨迹可能一个合规一个违规。

参考答案用异常类型区分审批缺失与结构非法，而不比错误文字。

重复write即使都发生在批准之后，仍不满足本课一次写入契约。

撤销后再次write必须失败，不能从历史中找到旧approved就放行。

生产轨迹需要稳定任务ID、序号和可信事件来源，模型不能自己生成审计事实。

端到端测试验证实际业务结果；本函数契约测试验证给定事件规则。

### Java Web迁移

Java可用enum表示事件并用switch推进状态；Python字符串更灵活，也更需要未知事件拒绝。审计轨迹验证类似状态机单元测试，不等于Spring事务回滚。
