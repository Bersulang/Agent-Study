# 阶段 45 知识：执行过程与回归测试

[返回讲义](README.md) · [全局知识手册](../../docs/knowledge.md)

### 1. 轨迹与最终答案

轨迹按顺序记录任务实际事件，例如 started、approved、write、finished。文本回答与执行轨迹分开验证；回答相同不意味着行为相同。不要把模型隐藏推理当审计依据。

### 2. 时序不变量

不变量是所有合法执行都必须满足的规则，例如写入前有批准、写入至多一次、结束后无动作。检查器在遍历事件时维护状态，发现违规直接失败。

### 3. 测试层次与契约

单元测试验证一个检查器；契约测试验证工具参数和事件格式；集成测试验证审批与数据库；端到端测试验证完整任务。与 Java 单元、接口和集成测试分层类似，不能全部依靠最慢的端到端测试。

## 执行过程

检查第一条是started；按事件更新批准和写入状态；write发生时同时检查授权、审批和是否重复；finished出现后禁止任何事件。最后要求有结束事件。

## 新语法

`elif` 表示互斥的后续条件；集合用于允许值判断；异常类型区分权限失败和数据格式错误，测试使用 assertRaises 验证失败路径。

## 判断与排错

| 答案正确但未审批 | 只评分最终文本 | 读取实际工具事件并检查时序 |
| 测试绑死每个模型步骤 | 断言不稳定的精确轨迹 | 检查业务不变量和允许的动作集合 |
| 重复写入没发现 | 只检查是否曾经成功 | 累计实际写入次数 |

## 工程边界

示例检查离线结构化事件。生产事件需由执行器或业务服务生成，不能信任模型自述“我批准了”；审批身份与参数绑定见阶段43。

## 复习问题

用一条“最终答案相同、轨迹不同”的案例证明检查有效；解释何时做契约测试，何时做端到端测试。

## 练习扩展与新验证边界

终态检查位于每次事件处理之前，因此finished后的read也拒绝。只读任务无需业务批准；含write的任务同时要求授权与当前有效批准。重复写入是契约错误，轨迹检查本身不会回滚远程副作用。
