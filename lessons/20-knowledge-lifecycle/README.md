## 概念：一篇文档的版本与整个索引的代次

导入知识时要回答两个不同问题：“这篇政策是第几版？”以及“索引整体经历过几次有效变化？”`version`属于单篇文档，`generation`属于整个索引。不能拿一个数字兼任两种含义：更新A文档会让A的version递增，也会让整体generation递增；更新B不会改变A的version。

下面摘录或简化本课示例的关键步骤，需结合[完整源码](examples/demo.py)中的定义与上下文阅读；运行时使用下方演示命令。

```python
index.update("policy", "限额500")
index.update("policy", "限额800")
print(index.documents["policy"]["version"], index.generation)
```

先预测：两次都是有效更新，因此输出为`2 2`。第一次建立policy v1/generation 1；正文改变后建v2/generation 2。若再次导入完全相同的正文和`expires`，摘要与元数据都相同，函数返回`unchanged`，两个计数都不变。反过来，只改`expires`也会建立新文档版本，因为同一正文在不同生效区间表达的是不同政策。

删除与过期也不能混为一谈。`visible(now)`用`now < expires`过滤过期文档，但记录仍留在字典中供审计；`delete`直接移除当前读入口并递增generation。若导入空文本，程序在修改字典前抛出`ValueError`，避免错误文件覆盖原来可用的政策。

<details><summary>展开推导：先写入限额500并设expires为10，再重复导入相同内容和期限，最后把expires从10改为20，版本与generation怎样变化？</summary>

第一次写入后是version 1、generation 1。相同正文且相同expires命中`unchanged`，仍是1和1。只把expires改成20也属于有效元数据变更，因此version 2、generation 2。摘要只覆盖正文，不能单独决定文档是否相同。
</details>

Java对照：数据库里可以用文档行的`version`做乐观锁，再用索引构建记录的`generation`标记一次整体切换。单篇内容相同不代表生效区间相同；生产更新还需事务或原子索引切换，本例内存字典不提供这些保证。

第一次插入policy返回updated；正文从限额500变800再次返回updated并生成version 2。随后删除policy，所以最后打印的documents为空字典。示例未打印generation，但每次有效更新或删除都会递增它。

## 执行过程与状态变化

1. 初次导入创建v1。
2. 相同指纹跳过修改。
3. 内容变化创建v2，generation增加。
4. 删除清除唯一读入口，不再提供旧答案。

执行轨迹是：首次导入建v1；内容变化建v2；删除后字典为空。空文本检查发生在赋值之前，避免无效内容覆盖当前有效版本。

## 逐行阅读与Python语法

`self.documents`属于Index实例，不同实例彼此隔离。`visible`对行使用`dict(row)`返回副本，调用者改结果不会污染索引。`expires=None`表示没有截止时间，整数时钟只是测试方便；真实服务需统一带时区时间。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `self.documents` | 属于这个Index实例；两个实例的字典不同。不要定义成类级共享可变字典。 |
| `old = ...get(identity)` | 不存在得到None；已有记录才能取version递增。 |
| `unchanged早返回` | 相同摘要不增加generation，避免重复导入不断制造无意义索引版本。 |
| `空文本检查先行` | 在计算摘要和赋值前拒绝，原有效知识不会被失败导入覆盖。 |
| `del self.documents[identity]` | 删除读入口；重复删除先判存在，不抛KeyError。 |
| `generation` | 表示索引整体变化次数，不能代替每篇文档version或数据库事务编号。 |
| `迁移策略` | 新embedding模型需构建新索引与评估、核对删除和权限、再切换；不能在同一个向量空间混入新旧模型。 |

## 工程延伸与边界

`update(identity, text, expires=None)`中的None表示没有失效期限；`visible(now)`只返回当前有效的资料副本。
生效元数据也是版本内容：同一正文把expires从10改为20，版本仍需递增。过期边界使用now>=expires，不允许第10时刻继续读取第10时刻失效的文档。
本例整数时间是教学用时钟，生产使用带时区时间戳。过期可保留审计记录，删除则清除当前读入口，两者保留策略不同。
新增test_expiry.py先因缺少expires参数失败，之后实现边界过滤与元数据版本规则再通过。

内存索引没有数据库事务、跨进程一致性或缓存失效保障。生产删除必须覆盖源、向量库、缓存与备份保留策略。

从本课迁移到企业项目时，先写输入输出契约与独立评估案例，再决定存储、模型和框架。
保留可追溯来源和任务/身份信息，让问题能定位到具体数据与步骤。
添加性能优化前先检查正确性，尤其是失败时是否仍保护权限、预算和有效状态。
单元测试覆盖本地规则；真实网络、持久化、并发与供应商行为需要额外集成验证。
