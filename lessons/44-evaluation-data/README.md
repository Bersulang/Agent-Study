## 1. 业务场景

企业助手换了提示词以后，演示题仍然答对，但无答案问题开始编造。我们建立带人工标签的评估集，让“更好”变成可以核查的指标。

## 2. 学习目标与前置知识

## 3. 关键概念

### 1. 评估集与泄漏

评估集保存未用于提示词调优的任务及期望行为；训练或调试用例与验收集分开。例如无资料的问题应回答 unavailable，而不是猜测。把验收答案写入提示词会造成数据泄漏，分数不再代表泛化能力。

### 2. 分层指标与硬性门槛

成功率是通过任务数除以总任务数；按正常、无答案、越权分别计算，避免大量简单题掩盖安全失败。权限违规属于硬性失败，即使总体成功率很高也不能发布。Java 测试中也常把安全断言独立于平均性能指标。

### 3. 人工评审与模型评分

模型评分是辅助判断，不是事实来源。下面对人工标签与模型标签计算分歧，交由人工复查。正式盲评隐藏版本信息，评分标准写出引用正确、事实正确与拒绝正确，而不是仅问“回答好吗”。

## 5. 代码执行过程与新语法

先按 case_id 校验预测数量，缺失或重复预测立即报错；然后逐条对照人工行为标签，累计总体与类别指标；最后列出硬性门槛违规。模型评分分歧单独输出，不覆盖人工真值。

### 本课语法提示

`Counter` 是计数容器，读取不存在的键得到零；字典推导式把记录转成ID索引；`int(True)` 得到1，可用于累计通过数。

函数的参数表示需要提供的信息，返回值表示结果。异常表示当前调用不能继续，不能简单吞掉所有异常；需要将失败类别传给上层处理。注释与讲义共同解释关键决策。

## 6. 常见错误与排查

| 症状 | 原因 | 排查与修复 |
| --- | --- | --- |
| 分数很高但越权 | 正常题太多掩盖攻击题 | 按类别报告并设置安全硬门槛 |
| 缺失案例被忽略 | 只遍历预测结果 | 以完整评估集为准核对ID |
| 模型评分永远同意 | 评审模型知道候选版本或评分标准太含糊 | 盲评、抽样复核并保存分歧 |

排查时保留输入类别、状态与错误码；涉及身份、密钥和业务数据时，先脱敏再记录。一次运行成功只能证明当前案例，必须覆盖变化后的需求和失败路径。

## 源码分段追踪与Java对照

### 输入和初始化

评估输入包含案例ID、类别和人工期望动作；预测只包含ID与候选动作。

CASES不是用户流量样本，三个固定案例只能验证计分逻辑，不能推断真实模型质量。

expected_ids与actual_ids先取ID，避免只按列表位置配对而误判。

Counter统计每个ID的出现次数，比set比较多检查了重复预测。

空案例集不能除以零，也没有可解释的成功率，因此直接拒绝。

### 校验与状态推进

案例ID重复说明评价对象不唯一，计算指标前必须修复数据。

by_id按案例ID查候选动作，预测列表调换顺序不会改变结果。

totals按类别加一；passes把布尔correct转成0或1累加。

“不完整参数”案例即使候选答错，也必须进入分母。

安全错误另收集violations，平均分不能抵消一次越权。

by_category保存每类通过率，帮助找到被大类别掩盖的失败。

release_allowed字段只表示安全门槛，需要release_decision进行完整发布判断。

release_decision同时检查总体0.9、每类0.8和无安全违规。

### 失败与验证证据

这两个质量门槛是练习约定值，不是企业统一标准。

all逐项检查类别值；类别集合为空时另外拒绝，避免空all返回True。

参考答案构造总分0.95但小类别0的报告，证明分类门槛必要。

disagreements只报告不同评价，不自动认定模型评分正确。

评分ID集合不一致先报错，不能把缺失分数看成零或默认通过。

新增标签前先定义clarify含义：需要参数补充，尚未创建业务结果。

失败预测的异常是数据契约问题，不能偷偷删除失败案例提高指标。
