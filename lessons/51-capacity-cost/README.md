## 3. 关键概念

### 1. 令牌桶与背压

令牌桶按速率补充额度，容量控制突发；没有额度时拒绝或排队。背压将下游容量不足反馈给上游，队列不能无上限。这里的额度Token不是模型Token。

### 2. 延迟分位数

平均延迟掩盖慢请求。p95说明约95%的请求不比它更慢；需要同时观察吞吐、错误率、负载与任务类别。样本太小只能做演示。

### 3. 模型预算与降级

总预算包含所有子Agent、重试和检索。资源不足时可用更简单流程或请求稍后重试，但不能降低授权和数据隔离。缓存必须保留tenant与行为版本范围。

## 5. 代码执行过程与新语法

令牌桶按传入单调时间补充额度，所有请求先检查成本和剩余额度；分位数使用排序后的近邻秩定义；默认使用手动时钟避免测试依赖真实等待。

### 本课语法提示

类把额度和最后更新时间保存在self中；ceil向上取整；`_`表示循环变量不参与计算；时间由调用者传入便于确定性测试。

函数的参数表示需要提供的信息，返回值表示结果。异常表示当前调用不能继续，不能简单吞掉所有异常；需要将失败类别传给上层处理。注释与讲义共同解释关键决策。

## 6. 常见错误与排查

| 症状 | 原因 | 排查与修复 |
| --- | --- | --- |
| 限流失效 | 各进程持有独立桶 | 生产用共享原子存储或网关限流 |
| 平均很快但用户抱怨 | 忽略p95和错误率 | 在目标负载下分层观察 |
| 降级导致越权 | 省略权限检查 | 安全约束不参与性能降级 |

排查时保留输入类别、状态与错误码；涉及身份、密钥和业务数据时，先脱敏再记录。一次运行成功只能证明当前案例，必须覆盖变化后的需求和失败路径。

## 源码分段追踪与Java对照

### 输入和初始化

capacity是桶最大额度，rate是每秒恢复额度，不是并发线程数。

初始化tokens=capacity，所以第一次请求可立即扣费。

allow使用传入手动时钟，测试不需要sleep。

cost必须正数，负成本不能反向增加额度。

now比last小表示时钟倒退，失败前不能修改tokens或last。

### 校验与状态推进

先计算经过时间乘速率，再加回额度。

min限制tokens不超过capacity，长时间空闲不能积累无限额度。

更新last后，如果余额不足，返回False而不扣费。

余额足够时减cost，返回True允许请求。

False是合法限流结果，与配置错误抛异常不同。

A与B使用两个不同TokenBucket实例，A耗尽不影响B。

零剩余tokens合法，等待一秒可恢复；零capacity配置直接拒绝。

参考答案先用完A，再请求B，证明不是共享同一个桶。

### 失败与验证证据

失败用例保存(tokens,last)并比较，保证非法输入无状态变化。

percentile排序样本，ceil(n*fraction)-1取得最近秩定义的位置。

20条样本的p95位置为第19条，因此结果是200。

平均值39能掩盖尾部200与400，不能只凭平均值设计超时。

这些数字是固定夹具，不是测量当前模型或机器延迟。

限流限制单位时间请求量；并发限制在途任务；队列长度限制等待任务。

多进程各自内存桶会放大总额度，生产需原子共享存储或统一网关。

### Java Web迁移

TokenBucket类似Java网关限流器；Python对象与Java对象都不会自动跨进程共享。perf_counter类时钟与Java System.nanoTime适合相对时间，不能替代审批的绝对日期。
