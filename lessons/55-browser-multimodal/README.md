## 1. 业务场景

助手需要从页面查询工单，或读取图片和录音。一次点击不代表操作成功，模型能接收图片也不代表能正确理解。我们先练动作确认与输入限制，再提供真实浏览器、图像与语音接入。

## 2. 学习目标与前置知识

能区分页面动作与业务确认、声明媒体类型与真实解析、内存去重与持久幂等。

先完成前面的 Python、工具、状态和协作基础。本课重点是理解机制，能够修改并验证代码。遇到不理解的语法先查看本课语法说明，再回到基础阶段复习。

本课把已有机制组合为一条完整请求路径。验收时需要能解释正常结果、失败前后的状态，以及新需求加入后哪些旧约束仍然成立。

## 3. 从问题建立机制

### 点击完成，业务为什么可能还没完成

浏览器自动化定位到提交按钮并成功click，只说明浏览器执行了动作。服务器可能拒绝、超时，也可能已经创建工单但页面没收到响应。判断成功应看后置条件，例如确认页出现的工单ID，必要时再查询服务端状态。

本课先用PageTask把状态做小：初始opened且ticket_id=None；未审批时立即拒绝；批准后首次提交得到教学ID并转confirmed；再次提交复用已有ID。这个类不驱动浏览器，只让“检查动作结果”变成可观察的状态变化。

### 重试之前先确认上一次发生了什么

若每次页面超时都重新点提交，很容易创建重复工单。演示在同一个PageTask实例中保存ticket_id，所以重试能返回同一值；进程重启或换一个实例则不能依靠这块内存保证幂等。真实业务应使用服务端幂等键与查询结果，页面点击次数不是可靠账本。

登录过期、验证码或页面结构改变应分类处理：暂停并人工接管，保存可恢复状态，避免无限尝试。状态记录需要足够定位任务，但不应把Cookie、凭证或完整敏感截图当普通日志保存。

### 图片或录音能上传，不代表内容已被正确理解

check_media只检查声明的MIME与大小。MIME类似HTTP Content-Type，表示声称的数据类型，不能证明字节内容真的是PNG或WAV。后续解析器还要核对实际格式、资源消耗与来源。

OCR可能把账号中的0识别成O，语音转写可能漏掉“不”字。识别结果进入业务前需要结构校验与风险相应的确认；不能把模型从图片里读到的“已批准”当成可信审批。

### 从状态教具走到真实浏览器

读懂PageTask后，再按[集成说明](integrations/README.md)操作本地HTML页面，比较定位、输入、点击与确认这四步。Playwright或Java Selenium都需要可靠定位与等待条件，不应以固定sleep代替结果判断。图像和音频模型是另一个独立接入层，没有下载模型或运行服务时保留待验证状态。

<details><summary>先预测：首次submit(False)失败后，再submit(True)，会因为前一次失败而跳过审批或直接返回空ID吗？</summary>

不会。失败发生在状态修改之前，仍是opened和None。第二次有批准才创建教学ID并转confirmed；下一次重复提交才可复用这个ID。

## 5. 跟踪一次完整执行

对照[源码](examples/demo.py)中的两个独立机制：

| 操作 | 之前状态 | 结果 | 之后状态 |
| --- | --- | --- | --- |
| submit(False) | opened / None | PermissionError | 不变 |
| submit(True)首次 | opened / None | DEMO-T-001 | confirmed / 同一ID |
| submit(True)重复 | confirmed / 已有ID | 复用ID | 不变 |
| check_media(image/png,100) | 无页面状态参与 | 返回媒体元数据 | 不改变页面任务 |

`is None`用来判断尚未保存结果，与ID字符串是否为空是不同条件。媒体检查的`0 < size <= maximum`同时要求非空和不超限，不能只检查上限，否则零字节文件会被当成有效输入。

默认媒体允许集合与练习适配器的集合不同：演示用于图片、语音等元数据边界，独立练习接口按练习页规定。不要把两份接口混成同一套已经测试过的真实上传服务。

## 6. 常见错误与排查

| 症状 | 原因 | 排查与修复 |
| --- | --- | --- |
| 点击成功但没创建 | 只检查click没有检查结果 | 断言提交后的可见ID或服务端状态 |
| OCR错字变成业务参数 | 未经复核直接执行 | 结构化校验和必要人工确认 |
| 登录失效无限重试 | 失败未分类 | 识别认证故障后暂停并人工接管 |

排查时保留输入类别、状态与错误码；涉及身份、密钥和业务数据时，先脱敏再记录。一次运行成功只能证明当前案例，必须覆盖变化后的需求和失败路径。

## 9. 企业工程边界

真实页面和媒体接入需分别记录证据：页面动作核对后置条件，图片或语音核对识别内容。一次页面提交成功不能证明图像识别准确，MIME检查通过也不能证明解析器安全。

默认示例是页面状态教具而非真正浏览器。集成目录含Playwright本地页面、Ollama图像调用、faster-whisper音频转写；模型文件和服务需额外安装，不默认下载或调用。PDF与表格导入关联阶段17。

生产接入需要按场景明确身份、数据保留、故障恢复、容量和发布策略。本课程案例的验证范围是本地确定性行为，未调用真实外部模型或声称在生产环境通过。
