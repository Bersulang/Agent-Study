## 概念：先缩小可见范围，再比较证据

权限过滤必须发生在检索结果交给回答逻辑之前。示例资料有HR专属、ENG专属和公开三类；`search`先验证调用者部门是否在允许集合，再逐篇判断资料部门是否等于当前部门或`*`，最后才做词项匹配。

下面摘录或简化本课示例的关键步骤，需结合[完整源码](examples/demo.py)中的定义与上下文阅读；运行时使用下方演示命令。

```python
if doc["department"] not in {department, "*"}:
    continue
if set(query.split()) & set(doc["text"].split()):
    results.append(doc["id"])
```

预测输入`search("薪资 工单", "ENG")`：HR资料含“薪资”，但先被权限条件跳过；ENG资料与公开资料都含“工单”，所以按输入顺序得到`["eng", "public"]`。如果把词项匹配放在授权前并把候选文本交给模型，即使最终答案不引用HR文档，敏感内容也已经越过边界。

同一事实冲突时，`detect_conflict`收集所有`value`，只在不同值个数大于1时返回True。它能指出500与800不能被静默合并，却不能决定哪一份政策有效；还要根据生效时间、来源权威和版本规则处理。

Java对照：可把部门过滤放进Repository查询条件或数据库行级安全策略，再对已授权记录做排序。先查全部资料再在Controller隐藏结果会让日志、缓存或模型上下文提前暴露数据。

### 默认演示预期输出

```text
['eng', 'public']
True
```

### 预期输出如何阅读

ENG查询薪资和工单，只命中ENG资料eng与公共资料public；HR记录在检查正文词项之前已过滤。第二行True表示两条事实记录的value集合含有多个值，系统应保留冲突而不是挑一个。

## 执行过程与状态变化

1. 验证可信部门值。
2. 过滤不可见记录。
3. 仅对授权正文计算词项交集。
4. 独立检查事实值集合并标记冲突。

输出`['eng', 'public']`表示过滤后的相关资料ID；第二行True表示两个事实值不同。这里没有把被过滤资料的标题写进结果，避免权限错误本身成为侧信道。

在多租户练习里，不要只给函数增加tenant参数，还要把tenant纳入候选过滤和`cache_key`。缓存命中前必须确认身份范围相同，否则缓存会绕过正确的检索过滤。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `department合法集合` | 未知身份默认拒绝；不能把不认识的部门当公共用户继续查询。 |
| `{department, "*"}` | 公共资料与当前部门资料允许读；HR资料不能因为问题相关而进入ENG候选。 |
| `continue` | 直接跳到下一条，后面的正文分词和计分不会执行。 |
| `结果只输出id` | 检索层仍需下游引用接口校验身份，防止通过已知id绕过正文读取权限。 |
| `values集合` | 多个不同值意味着冲突；同值多来源不算数值冲突，但还需核对生效时间和来源权威性。 |
| `PermissionError` | 授权失败不是no_evidence；日志可记录受控原因，用户输出不应泄露被过滤文档标题。 |
| `验收对照` | 用同一个问题分别以HR和ENG查询，比较结果差异；再测公共资料、未知部门、租户缓存与冲突资料。 |

## 易错点与排错顺序

1. 文件路径错误：确认终端在项目根目录，先运行演示而不是练习骨架。
2. 把空结果当成功：查返回状态与来源，不能编造缺失字段或证据。
3. 在失败后继续修改：先验证再变更，给失败输入补行为测试。
4. 共享可变对象：调用前后打印输入，确认是否被无意修改。
5. 把模拟效果当生产质量：检查本页边界说明与真实接入目录。
6. 只看最终回答：保留查询、状态或执行轨迹，定位失败发生在哪一步。
