## 概念

### 1. 身份上下文

定义：由可信认证层确定的用户与部门。

用途：解决本场景中身份上下文的责任边界。

具体例子：不能让模型自行声明自己是HR。

检查问题：如果这个信息缺失，哪一步会失败或产生误导？

### 2. 检索前过滤

定义：先限制候选集合，再计算相关性。

用途：解决本场景中检索前过滤的责任边界。

具体例子：工程用户完全不接触HR正文。

检查问题：如果这个信息缺失，哪一步会失败或产生误导？

### 3. 冲突证据

定义：同一事实的有效资料互不一致。

用途：解决本场景中冲突证据的责任边界。

具体例子：两个有效政策给出不同限额。

检查问题：如果这个信息缺失，哪一步会失败或产生误导？

### 4. 覆盖率

定义：验证应该可见的知识是否被正确检索。

用途：解决本场景中覆盖率的责任边界。

具体例子：授权资料漏检也属于质量问题。

检查问题：如果这个信息缺失，哪一步会失败或产生误导？

## 逐行阅读与Python语法

先找到 `def` 或 `class`，这是函数或类的定义，不会在定义时自动完成业务调用。
函数括号内是参数，调用时实参传入这些名字；`return`结束当前函数并交还结果。
`if` 根据条件选择分支，冒号后的缩进属于该分支；Python不使用Java花括号表示代码块。
`for item in items` 逐个遍历对象；字典直接遍历得到键，`.items()`同时提供键和值。
列表推导式 `[x for x in rows if condition]` 等价于新建列表、遍历、判断、append。
集合 `set(...)` 自动去重；`&` 是集合交集，用来保留同时出现的元素。
字典 `.get(key)` 在键不存在时返回None，直接 `[key]` 则可能抛KeyError。
`raise` 抛出异常，调用者可以用 `try/except` 区分明确错误类型。
`dict(row)` 只做浅复制，嵌套列表仍可能共享；本例字段简单，生产要明确所有权。
`lambda` 是小的匿名函数，本课排序键只负责返回排序依据，不应夹带写入副作用。
`if __name__ == "__main__"` 只在直接运行时执行入口，被测试导入时不打印演示。
出现Path、hashlib、json或tempfile时，它们都是标准库；结合源码注释看具体调用目的。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `department合法集合` | 未知身份默认拒绝；不能把不认识的部门当公共用户继续查询。 |
| `{department, "*"}` | 公共资料与当前部门资料允许读；HR资料不能因为问题相关而进入ENG候选。 |
| `continue` | 直接跳到下一条，后面的正文分词和计分不会执行。 |
| `结果只输出id` | 检索层仍需下游引用接口校验身份，防止通过已知id绕过正文读取权限。 |
| `values集合` | 多个不同值意味着冲突；同值多来源不算数值冲突，但还需核对生效时间和来源权威性。 |
| `PermissionError` | 授权失败不是no_evidence；日志可记录受控原因，用户输出不应泄露被过滤文档标题。 |
| `验收对照` | 用同一个问题分别以HR和ENG查询，比较结果差异；再测公共资料、未知部门、租户缓存与冲突资料。 |

## Java Web对照

Python字典类似 `Map<String, Object>`，但动态键更容易遗漏字段，所以业务边界必须检查。
Python集合类似 `HashSet`，列表类似 `ArrayList`；不能把集合顺序当稳定业务顺序。
纯函数类似Service方法：接收明确输入，返回结果；控制器/入口负责展示。
`ValueError`类似参数非法，`PermissionError`类似授权失败；两者不应统一当作可重试网络错误。
Python没有编译器保证字典字段齐全；后续可用数据类或Schema校验，但类型标注本身不做运行时验证。
Java中的事务、数据库和Spring Security不会因迁移到Python而自动存在，必须明确设计与验证。

## 易错点与排错顺序

1. 文件路径错误：确认终端在项目根目录，先运行演示而不是练习骨架。
2. 把空结果当成功：查返回状态与来源，不能编造缺失字段或证据。
3. 在失败后继续修改：先验证再变更，给失败输入补行为测试。
4. 共享可变对象：调用前后打印输入，确认是否被无意修改。
5. 把模拟效果当生产质量：检查本页边界说明与真实接入目录。
6. 只看最终回答：保留查询、状态或执行轨迹，定位失败发生在哪一步。

## 工程延伸与边界

内存过滤只是权限机制演示，不是认证系统；实际索引、缓存、日志和引用接口都必须继承可信身份约束。

从本课迁移到企业项目时，先写输入输出契约与独立评估案例，再决定存储、模型和框架。
保留可追溯来源和任务/身份信息，让问题能定位到具体数据与步骤。
添加性能优化前先检查正确性，尤其是失败时是否仍保护权限、预算和有效状态。
单元测试覆盖本地规则；真实网络、持久化、并发与供应商行为需要额外集成验证。
