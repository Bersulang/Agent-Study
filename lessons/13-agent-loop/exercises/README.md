# 阶段13独立练习

完成课程演示后，关闭参考答案，修改 `practice.py` 中的 `solve(data)`。
练习与演示共享概念，但新增行为由你实现。

## 迁移练习：由工具观测决定下一步

在独立的[`feedback_practice.py`](feedback_practice.py)中实现`solve_feedback(ticket, owners)`。`ticket`含`id`和`status`；`owners`将工单id映射到负责人名字。模型替身接收消息历史：它先查询工单，再根据工单观测决定查询负责人或直接结束；最终文本来自工具观测。由你定义并说明消息结构。

至少覆盖开放/关闭两种工单结果，并证明它们实际执行了不同后续动作；同时覆盖未知工具或工具拒绝、预算停止。错误结果不能伪装成成功。只使用只读模拟工具，不实现真实模型或写入业务系统。

基础动作列表练习继续使用[`practice.py`](practice.py)的`solve(data)`契约；反馈循环是第二个独立骨架，不复用或改写基础函数签名。先写输入/输出示例和失败行为，再实现循环；两个练习完成并自测后，再看solutions下对应参考答案。

## 业务需求

实现solve(data)：data为动作列表，支持只读search和final，最多3步，未知工具直接停止；返回trace与reason。search接收query且不得空白；final不能为空。解释一步是否包含最终回答。

## 工作顺序

1. 写出输入、输出、拒绝条件和状态变化。
2. 先列成功、边界、失败三类案例及预期。
3. 实现后从项目根目录执行 `python lessons/13-agent-loop/exercises/practice.py`。
4. 加入调用solve的代码，展示案例结果；当前骨架只报告待实现状态。
5. 解释每个分支为何存在，并保留原始输入以检查是否意外修改。

## 验收

- 独立完成上述新增业务行为，并给出实际命令和输出。
- 至少一个正常案例、一个空/缺失案例、一个失败案例。
- 能指出异常或拒绝发生在哪一层，不能把失败打印成成功。
- 能现场改变一个输入并预测结果，然后实际验证。
- 完成后才阅读 [参考答案](../solutions/solution.py)，说明与你实现的差别。
- 反馈循环完成后才阅读[反馈练习参考答案](../solutions/feedback_solution.py)，分别解释开放/关闭状态如何改变实际工具轨迹。

材料运行通过不代表学员能力通过；验收由实际讲解与修改证据决定。
