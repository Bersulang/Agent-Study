# 阶段38复习：架构选择的质量门

关联：[讲义](README.md)、[比较示例](examples/demo.py)、[练习](exercises/README.md)。

固定同一组政策、工单、组合问题，比较single/workflow/multi。只有全部答对才进入eligible，再按成本选最低者。故意让workflow在组合问题失败后，它必须退出候选；再便宜也不能越过质量门。

教学成本是逻辑单位，不是价格或延迟测量。真实评估需共享问题集并记录质量、权限错误、工具轨迹、p95和费用。阶段38允许预习，正式选择最好等39—43服务闭环跑通后再比较。


## 进一步检查

选择函数把“全对”当质量门，这是三道固定题的课堂规则，不代表生产可只测三题。单Agent示例漏掉组合问题是某个有限实现的性质，注释明确不推广成所有单Agent都不能组合回答。若没有合格实现，selected为none，意味着需要改进而不是自动降低标准。

成本只在eligible里比较，逻辑单位不是实际费用；p95、质量和成本应分别记录，不要用平均延迟遮住尾部慢请求。准备正式结论时固定测试集、预先约定阈值，再运行不同架构并保存相同口径的证据。
