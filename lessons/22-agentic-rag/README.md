# 阶段 22：受预算控制的Agentic RAG

## 使用场景

复杂问题同时问发票与审批，需要按缺失证据继续检索，不能无止境重试。

- 能预测complete、partial及预算停止结果，并解释trace与evidence不同。

## 概念：研究计划是有上限的循环

单次检索只问一个问题；Agentic RAG会按给定topics逐项查找，但每次新查询都占用预算。`evidence`保存已经找到的答案，`trace`记录实际执行过的查询，`missing`列出仍没有证据的主题。它们用途不同：trace里出现一次查询并不等于已经找到证据。

下面摘录或简化本课示例的关键步骤，需结合[完整源码](examples/demo.py)中的定义与上下文阅读；运行时使用下方演示命令。

```python
for topic in topics:
    if topic in evidence:
        continue
    if len(trace) >= budget:
        break
    trace.append({"query": topic, "step": len(trace) + 1})
```

对`["发票", "审批", "期限"]`且预算为2，循环先查询发票、再查询审批；两者都命中固定知识。查询期限前，`len(trace)`已经是2，于是停止。结果包含两条evidence、一条missing“期限”，状态是`partial`。如果topics重复，`evidence`已有该主题就跳过，不浪费预算。

<details><summary>展开推导：预算设为1，输入发票、审批、发票，查询次数和结果是什么？</summary>

第一项发票尚无证据且预算可用，因此查询一次并命中。第二项审批需要新查询，但trace长度已经等于1，循环停止。最后计算missing时`dict.fromkeys`去重，结果是审批；重复的发票已经有证据。状态为partial，trace长度为1。
</details>

Java对照：可把循环写成带`remainingBudget`的服务调用，并在每次远程检索后追加不可变trace事件。生产实现还要限制单次查询延迟、令牌和费用；本课预算只计查询轮次。

### 默认演示预期输出

```text
{'status': 'partial', 'evidence': {'发票': '需要有效发票', '审批': '付款前主管审批'}, 'missing': ['期限'], 'trace': [{'query': '发票', 'step': 1}, {'query': '审批', 'step': 2}]}
```

### 预期输出如何阅读

status=partial表示不是所有主题都有证据。发票和审批各消耗一次预算并保留在evidence/trace；期限进入missing。trace记录做过哪些查询，evidence只存实际命中，两者不能互相替代。

## 执行过程与状态变化

1. 输入已分解的子问题。
2. 按预算限制顺序检索。
3. 已有证据复用；记录查询轨迹。
4. 逐项计算缺失证据，部分成功仍保留有效结果。

每次循环依次检查“是否已有证据”“是否达到预算”“记录查询”“查知识表”。完成全部主题且无missing才complete；证据不全返回partial并保留已找到的内容。

## 逐行阅读与Python语法

`dict.fromkeys(topics)`会按首次出现顺序去重主题；这样missing顺序稳定，也能避免重复子问题在练习里浪费预算。`evidence`保留结果，`trace`保留尝试，两者的职责不能合并。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `len(trace) >= budget` | 每条记录代表一次真实查询决定；条件在查询前，预算为0时不会访问资料。 |
| `topic in evidence` | 本演示仅复用已命中的主题；未命中的重复词仍可能耗预算，练习要求补全去重。 |
| `dict.fromkeys(topics)` | 字典按首次出现顺序保留键，用来取得稳定且去重的主题集合。 |
| `missing` | 每个未覆盖子问题都列出，不能把找到一个答案当全部完成。 |
| `partial` | 部分成功保留证据，但不会为期限补编数字；人类可决定继续查还是缩小任务。 |
| `trace与evidence不同` | 查询尝试可以失败，因此轨迹条数不能等同有效证据数。 |
| `与基础RAG比较` | 普通RAG固定检索一次；本例按子问题迭代，成本可能更高。用同一问题集比较覆盖、调用数与延迟。 |

## 易错点与排错顺序

1. 文件路径错误：确认终端在项目根目录，先运行演示而不是练习骨架。
2. 把空结果当成功：查返回状态与来源，不能编造缺失字段或证据。
3. 在失败后继续修改：先验证再变更，给失败输入补行为测试。
4. 共享可变对象：调用前后打印输入，确认是否被无意修改。
5. 把模拟效果当生产质量：检查本页边界说明与真实接入目录。
6. 只看最终回答：保留查询、状态或执行轨迹，定位失败发生在哪一步。
