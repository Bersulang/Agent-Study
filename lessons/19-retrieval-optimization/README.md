## 概念：先定位漏在哪，再调排序

`search`保留原词集合`raw`，再用别名表生成`expanded`。原词权重更高；“差旅 凭证”扩成“差旅、凭证、报销、发票”，命中A和B。文档C即使词面很接近，也会在打分之前因`active=False`被排除：旧政策不能靠分数重新进入结果。

下面摘录或简化本课示例的关键步骤，需结合[完整源码](examples/demo.py)中的定义与上下文阅读；运行时使用下方演示命令。

```python
score = 2 * len(raw & words) + len(expanded & words)
if score:
    ranked.append((score, doc["id"]))
```

先预测：如果A、B都返回但只标注A相关，precision是多少？1/2；recall是1/1。演示第二条`metrics(["A", "B"], ["A"])`则recall=0.5、precision=1.0。相关集合必须由人工/任务定义，而不能把检索返回结果自己当标准答案。

反例：若相关文档根本不在索引，调整排序无法找回；若相关文档在候选里却排在后面，才是排序问题。查询改写可能增加召回，也会引入噪声，所以要用固定困难问题集比较。练习中的RRF按照名次累加`1/(60+rank)`，融合候选排名，不依赖不同检索器分数处于同一尺度。

### 默认演示预期输出

```text
['A', 'B']
{'recall': 0.5, 'precision': 1.0}
```

### 预期输出如何阅读

差旅和凭证经别名扩展后命中A、B；inactive的C在打分前被排除。人工期望有A、B，实际只返回A，所以recall=1/2、precision=1/1。分数证明固定规则运作，不代表真实查询集上的指标。

## 执行过程与状态变化

1. 原查询保留用于诊断。
2. 同义词扩展增加候选覆盖。
3. 先筛active，再对重叠词加权排序。
4. 用人工相关集合计算指标，不能用最终回答替代检索指标。

从输入到指标：先生成候选、按score和id排序，再将结果与标注集合比较。先看候选是否含目标，再看排序位置；这样不会把召回失败误诊成重排失败。

## 逐行阅读与Python语法

`aliases[word] for word in raw if word in aliases`只取已定义的同义词，未知词不会触发KeyError。排序中的`(-score, id)`让高分优先、并列按id稳定。原查询必须保留在实验记录里，否则无法比较改写是否真正救回了困难问题。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `raw与expanded` | 保留原始词集合，改写只增加受控词；不要覆盖原查询导致无法定位改写错误。 |
| `aliases[word] for word in raw if word in aliases` | 只访问存在的映射键；if去掉会在未知词上抛KeyError。 |
| `active过滤` | 先排除失效资料，再评分；C即使包含所有词也不能进入结果。 |
| `2 * len(raw & words)` | 原词更高权重是教学规则，需要真实评估才能判断是否有效，不能把系数2当通用最佳值。 |
| `metrics的集合` | 相关集合由人工标注；去重避免返回同一id多次导致指标虚高。 |
| `空集合分母` | 本例定义无相关项/无返回项指标为0，评估报告要说明约定，避免除零和解释歧义。 |
| `失败定位` | 先问相关文档是否入候选，再问排序是否靠前，最后才检查回答是否误读；三类失败改法不同。 |

## Java Web对照

Java可用Comparator按加权分和id稳定排序；RRF按rank融合而非分值，需要保留原查询、改写查询和人工相关集合。

## 易错点与排错顺序

1. 文件路径错误：确认终端在项目根目录，先运行演示而不是练习骨架。
2. 把空结果当成功：查返回状态与来源，不能编造缺失字段或证据。
3. 在失败后继续修改：先验证再变更，给失败输入补行为测试。
4. 共享可变对象：调用前后打印输入，确认是否被无意修改。
5. 把模拟效果当生产质量：检查本页边界说明与真实接入目录。
6. 只看最终回答：保留查询、状态或执行轨迹，定位失败发生在哪一步。
