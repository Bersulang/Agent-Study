上一课的助手只能显示几行文字。现在客服交给它三张工单，希望先看到尚未关闭、优先级至少为 4 的那些工单，再知道这些工单来自哪些部门。怎样把这件事写成程序？

## 3. 给一个值起名字：赋值先做右边，再处理左边

假设工单的优先级是 4。只写 `print(4)` 能显示数字，却没有告诉读者这个数字代表什么。给它起一个名字，代码就能表达业务含义：

```python
# priority这个名字记录工单优先级。
priority = 4
print(priority)

# 先用原来的优先级计算，再把新结果绑定给同一个名字。
priority = priority + 1
print(priority)
```

输出依次是 `4`、`5`。第一条赋值中的 `=` 不是数学里的“左右永远相等”，而是一条操作指令。Python 先求右边表达式的值，再让左边的名字指向那个结果。

执行 `priority = priority + 1` 时，右边读取旧的 `priority`，得到 4；计算 `4 + 1`，得到 5；最后才把名字 `priority` 重新绑定到 5。因此这里不会形成无限循环，也不是把整数对象 4 改造成了 5。

“对象”可以先理解为程序里实际存在的值，它有类型和内容。“名字绑定对象”就是说，程序通过一个名字找到这个值。整数和字符串是不可变对象：不能原地改写它们的内容，但名字可以改为指向别的对象。

先预测下面的输出：

```python
# remembered记录的是此刻找到的整数对象，不是计算公式。
priority = 4
remembered = priority
priority = 5
print(remembered)
```

<details>
<summary>预测之后再看解释</summary>

输出是 `4`。`remembered = priority` 执行时，右边求值得到 4，所以 `remembered` 绑定到 4。后面只改变了 `priority` 的绑定，没有重新给 `remembered` 赋值。它不会自动跟着别的名字更新。

</details>

你在 Java 中熟悉 `int priority = 4`。Python 这里省略类型声明，但不是“数据没有类型”：4 仍是整数对象。暂时不要把 Python 变量完全等同于 Java 的基本类型变量；稍后列表共享的例子更接近 Java 的引用赋值。

## 4. 一张工单怎样表示：先读懂字典

一张工单不只有优先级，还有编号、部门和状态。我们可以用字典把这些信息放在一起：

```python
# 一个字典保存一张工单；键表示字段名，值表示字段内容。
ticket = {"id": "T1", "department": "IT", "priority": 5, "status": "open"}
print(ticket["id"])
print(ticket["priority"])
```

输出是 `T1` 和 `5`。这里的 `{...}` 创建字典；冒号分隔一个键和它对应的值，逗号分隔不同的键值对。`"id"`、`"status"` 是字符串键，`"T1"`、`"open"` 是字符串值，而 5 没有引号，是整数。

字符串是文本，可以包含中文。`"open"` 和 `'open'` 都表示相同文本，外层引号不属于文本内容。`"5"` 则是文本，不是整数 5；文本不能直接按数值与 4 做大小比较。本课输入已经给好类型，后面学习输入校验时再处理类型错误。

`ticket["id"]` 的方括号表示“在这个字典中按键查值”。它不是创建一个列表，因为方括号前面已有要访问的对象 `ticket`。若写成 `ticket["ID"]`，Python 不会猜测你想找 `"id"`，而会抛出 `KeyError`：键名区分大小写。

字典是可变对象。下面改的是这个字典内部的值，而不是重新创建整张工单：

```python
# 把已有工单从未处理改为已分派。
ticket = {"id": "T1", "status": "open"}
ticket["status"] = "assigned"
print(ticket["status"])
```

输出为 `assigned`。读值与写值的差别在于它位于赋值的哪一侧：右边读取，左边指定要更新的位置。

## 5. 多张工单怎样组织：列表中的每个元素是一个字典

字典解决“一张工单有多个字段”，列表解决“有多张工单”。

```python
# 外层列表保留工单的排列顺序；每个内层字典表示一张工单。
tickets = [
    {"id": "T1", "department": "IT", "priority": 5, "status": "open"},
    {"id": "T2", "department": "HR", "priority": 4, "status": "closed"},
    {"id": "T3", "department": "IT", "priority": 2, "status": "open"},
]
print(tickets[0]["id"])
```

输出为 `T1`。`[...]` 创建列表，逗号分隔元素。列表的位置从 0 开始，所以 `tickets[0]` 是第一张工单，不是“第零张业务工单”。

把 `tickets[0]["id"]` 拆成两步就容易读了：先用整数位置 `0` 在列表里取出第一个字典，再用字符串键 `"id"` 从字典里取出编号。两次都用方括号，但依据的对象不同，取值方式也不同。

你可以把这种结构与 Java 的 `List<Map<String, Object>>` 联系起来。Python 的语法更短，但仍需知道列表里放的是字典；短语法不会自动保证每张工单都有相同字段。

## 6. 怎样表达“未关闭且优先级高”：先算两个判断

我们先不考虑三张工单，只判断一张：

```python
# 比较产生布尔值True或False，分别表示条件成立或不成立。
status = "open"
priority = 5
print(status != "closed")
print(priority >= 4)
print(status != "closed" and priority >= 4)
```

三行都输出 `True`。`!=` 表示“不相等”，`>=` 表示“大于或等于”。`and` 在这里连接两个比较结果，要求二者都成立。

把第二张工单的状态代入，左边 `"closed" != "closed"` 已经是 `False`，组合条件就不成立。Python 的 `and` 会短路：左边为假时，不再求右边。这与 Java 的 `&&` 在布尔条件中的使用相似。不过 Python 的 `and` 一般返回某个操作数，并非在所有场景都返回布尔值；本例两边恰好都是比较表达式，所以结果是布尔值。

| 工单 | 未关闭？ | 优先级至少为4？ | 是否保留？ |
| --- | --- | --- | --- |
| T1：open，5 | True | True | 是 |
| T2：closed，4 | False | True（单独比较时） | 否，左侧已失败 |
| T3：open，2 | True | False | 否 |

注意 `=` 与 `==` 的区别：`status = "open"` 是赋值，`status == "open"` 才是比较。演示使用“不是 closed”，独立练习会改为“恰好是 open”。遇到 `assigned` 时，两种条件的结果不同，不能原样照搬。

## 7. 怎样逐张处理：追踪循环，而不是背循环语法

现在把“判断一张工单”重复应用到列表里的每一张工单：

```python
# 三条记录给出能入选、被状态排除、被优先级排除三种情况。
tickets = [
    {"id": "T1", "priority": 5, "status": "open"},
    {"id": "T2", "priority": 4, "status": "closed"},
    {"id": "T3", "priority": 2, "status": "open"},
]
urgent = []
for ticket in tickets:
    # 只把符合条件的编号加入结果，不改原来的工单。
    if ticket["status"] != "closed" and ticket["priority"] >= 4:
        urgent.append(ticket["id"])
print(urgent)
```

`urgent = []` 创建一个空列表，用来累计结果。`for ticket in tickets:` 表示依次取出 `tickets` 中的元素，把本轮元素绑定给名字 `ticket`，再执行缩进的代码。

这里没有自动复制工单：本轮的 `ticket` 就是列表中的那个字典。它不是编号，也不是位置。如果在循环内写 `ticket["status"] = "closed"`，会修改原始记录。

`if 条件:` 只有在条件为真时才执行下面更深一层的代码。冒号表示代码块即将开始；四个空格表示在 `for` 块里，八个空格表示同时在 `for` 和 `if` 块里。最后的 `print` 回到最左侧，因此只在循环全部结束后执行一次。

`urgent.append(...)` 调用列表的 `append` 方法，把括号中的一个对象加入列表末尾。“方法”先理解为通过对象调用的功能：点号找到 `urgent` 的 `append`，圆括号发起调用。它直接修改列表，无需再把调用结果赋回 `urgent`。

| 时刻 | ticket绑定到谁 | 条件结果 | urgent当前内容 |
| --- | --- | --- | --- |
| 开始前 | 尚未开始迭代 | — | `[]` |
| 第一轮 | T1字典 | True | `["T1"]` |
| 第二轮 | T2字典 | False | `["T1"]` |
| 第三轮 | T3字典 | False | `["T1"]` |

为什么只追加 `ticket["id"]`，不追加整个 `ticket`？当前需求只需要编号；保留字符串可以避免使用者通过结果中的字典去改动原工单。若需要完整记录，是否共享或复制应另作决定，不能假定 `append` 会复制。

**先预测：** 如果把 T3 的优先级改为 4，输出顺序会是什么？如果 `tickets` 为空，`print` 还会执行吗？

<details>
<summary>查看推导</summary>

第一问得到 `['T1', 'T3']`，因为循环按输入顺序访问，`append` 加到末尾。第二问仍输出 `[]`：循环执行零次，结果列表已经在循环前创建，循环外的打印照常执行。

</details>

## 8. 部门去重与展示：集合负责唯一，排序负责顺序

三个工单的部门是 IT、HR、IT。如果只想知道有哪些部门，就不应该把 IT 显示两次。集合适合表达“是否已经存在”。

```python
# set()创建空集合；{}创建的是空字典，两者不同。
departments = set()
departments.add("IT")
departments.add("HR")
departments.add("IT")
print(sorted(departments))
```

输出是 `['HR', 'IT']`。第二次加入 IT 不会增加一个重复成员。`add` 修改集合；`sorted` 读取集合，返回一个新的有序列表，便于稳定展示。集合本身不承诺供业务依赖的迭代顺序，所以不要把它当作排好序的列表。

这与 Java 中先用 `Set` 去重、再整理展示顺序的思路相似。还要分清“有几个部门”和“每个部门有多少张工单”：集合回答前者，不能保留重复次数；独立练习会用字典回答后者。

## 9. 为什么改别名会影响原记录：沿着对象关系找原因

现在回到赋值。对于整数，重新绑定一个名字不会改变另一个名字。对于列表，情况要区分“重新绑定名字”和“修改对象内容”：

```python
# 两个名字指向同一列表，列表里放着同一个工单字典。
tickets = [{"id": "T1", "status": "open"}]
alias = tickets
alias[0]["status"] = "assigned"
print(tickets[0]["status"])
```

输出是 `assigned`。执行 `alias = tickets` 时，右侧求值得到已有列表；这条赋值没有创建新列表。可以把关系画成下面这样，箭头表示“指向”：

```text
tickets ─┐
         ├──→ 同一个列表 ──第0项──→ 同一个字典 {status: "open"}
alias ───┘
```

`alias[0]["status"] = "assigned"` 沿着箭头找到那个字典，然后改写它的字段。用 `tickets` 再沿同样的关系读取，当然会看到新值。Java 中两个变量引用同一个 `ArrayList` 或 `Map` 时也有类似现象。

如果随后写 `alias = []`，则只是让 `alias` 指向一个新的空列表；`tickets` 仍指向旧列表。这两种操作不能混为一谈。

### 复制一层为什么有时够用，有时不够

```python
# 先复制字典，再修改原字典中的字符串字段。
ticket = {"id": "T1", "status": "open"}
snapshot = ticket.copy()
ticket["status"] = "assigned"
print(snapshot["status"])
```

输出为 `open`。`.copy()` 创建了一个新字典，所以给原字典的 `status` 键重新放入一个字符串，不会改掉副本的这个键。

但是复制一层只复制外层容器。先预测这个变式：

```python
# 两个外层字典不同，tags却仍指向同一个内层列表。
ticket = {"id": "T1", "tags": ["网络"]}
snapshot = ticket.copy()
ticket["tags"].append("紧急")
print(snapshot["tags"])
```

<details>
<summary>查看对象关系与结果</summary>

输出为 `['网络', '紧急']`。`ticket` 和 `snapshot` 是两个字典，但它们的 `tags` 值指向同一个列表。`append` 修改的是这个共享列表，不是给某个外层字典重新设置键。所谓“浅复制”，就是新建外层容器，而没有递归复制里面的所有对象。

深复制可以处理部分隔离需求，但不是本课默认做法；先弄清哪些对象应该共享，再决定复制边界。后续状态管理也会重复使用这种分析方法。

</details>

### 元组固定的是哪些内容

```python
# 小括号中的两个字符串组成元组，表示此刻的编号与状态。
pair = ("T1", "open")
print(pair[0])
```

输出为 `T1`。元组与列表一样可按位置取值，但不能执行 `pair[1] = "closed"` 来重新设置其中的元素，否则会得到 `TypeError`。本例的两个元素又都是不可变字符串，所以很适合表示一组不会被原地改写的简单值。

不要把“元组不可变”理解为“任意嵌套内容都不可变”。如果元组里放的是列表，不能换掉那个元素，却仍可能修改列表内部。本课用字符串组成快照，正是为了让这个边界简单清楚。

## 11. 从演示走向练习：先补两个必要工具

### 用字典累计：读旧值，加一，再写回

```python
# 这是颜色计数的小例子，用来理解字典读取和更新的差别。
counts = {}
color = "蓝色"
previous = counts.get(color, 0)
counts[color] = previous + 1
print(counts)
```

输出 `{'蓝色': 1}`。`counts.get(color, 0)` 的意思是：如果有这个键，就取已有值；如果没有，就暂时返回默认值 0。`get` 本身不写入键，真正改变字典的是下一行赋值。

**自己试一次：** 再执行一次“读取旧值”和“写回加一”这两行，结果应是多少？若先把 `counts = {}` 也重新执行，为什么又变成 1？这个问题能帮助你判断累计容器应该放在循环外还是循环内。

### 练习骨架里的def和return先怎样使用

```python
# 定义一个可反复调用的处理步骤；此时不会打印或计算调用结果。
def add_one(number):
    result = number + 1
    return result

# 调用时，number收到4，返回值5交给answer。
answer = add_one(4)
print(answer)
```

`def` 定义函数，函数名后圆括号里的 `number` 是接收输入的参数名。冒号和缩进决定函数体范围。调用 `add_one(4)` 时才执行函数体；`return` 把结果交给调用者，并结束本次调用。`print` 只负责显示，两者用途不同。

你这节只需使用已经提供的 `solve(data)`：`data` 接收工单列表，`return` 交出结果。阶段03再系统展开调用、作用域和模块。骨架中的 `raise NotImplementedError(...)` 是“还没实现”的显式提示，写出自己的逻辑后应替换它。文件末尾已有的启动部分可以保留，不需要现在理解 `__name__` 的全部机制；自动检查器会直接调用你的 `solve`。

## 13. 易错点与定位方法

| 现象 | 先检查什么 | 为什么 |
| --- | --- | --- |
| `KeyError: 'department'` | 当前记录是否有该键、拼写是否一致 | 按键访问不会猜测字段 |
| `urgent`突然变成None | 是否写了`urgent = urgent.append(...)` | append原地修改列表，其返回值是None |
| 只剩最后一张工单的结果 | 是否把结果容器初始化放进循环 | 每轮重新创建容器会丢掉前面累计 |
| 修改结果后输入也变了 | 是否把原字典直接放进结果列表 | append不会复制字典 |
| 部门顺序偶尔变化 | 是否直接遍历集合展示 | 集合不承诺业务展示顺序 |
| assigned被错误算作open | 是否用了`!= "closed"` | “不等于closed”包含更多状态 |

遇到错误先看最后一行异常，再回到对应代码。不要为了让脚本继续跑就吞掉错误；先检查你对输入、对象关系和分支条件的理解。

## 14. 怎样判断这一课真正学会了

不用背定义，尝试完成下面三件事：

1. 对一个没见过的工单列表，先写出每轮的结果容器，再运行核对。
2. 指着`alias = tickets`和`alias[0]["status"] = ...`解释，哪一步只改变名字，哪一步修改共享对象。
3. 给工单加一个`tags`列表，解释浅复制为什么不能隔离标签修改；再指出当前练习是否真的需要深复制。

能做出这些解释，再进入阶段03，函数就不再只是新语法，而是把你已经理解的数据处理过程组织起来的方法。复习时使用[本课知识整理](knowledge.md)。
