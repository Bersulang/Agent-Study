# 阶段 54 知识：受控编码与数据分析助手项目

[返回讲义](README.md) · [全局知识手册](../../docs/knowledge.md)

### 1. 补丁与验证闭环

计划—修改—测试—审查是编码任务的基本闭环。这里补丁范围绑定文件、旧内容和批准的新内容；最终必须以实际测试输出验证，不能相信助手说已修复。

### 2. 进程隔离与沙箱边界

subprocess使用参数列表、超时和确定目录；不使用shell=True。Python -I只是隔离Python环境变量与导入路径，不是安全沙箱。不可信代码需容器或专用执行服务。

### 3. 只读SQL与最小数据范围

数据库只读连接阻止写入，但仍可能泄漏读取范围。预定义报告、租户参数和行数限制共同生效；参数绑定不能替代SQL结构权限。

## 执行过程

先将已知错误程序写入临时空间；限定补丁函数拒绝其它文件与不匹配内容；运行固定本地测试，返回有限输出；数据报告只接受枚举报告类型，用参数绑定租户。默认不执行模型生成的任意程序。

## 新语法

`subprocess.run`等待子进程并收集结果，timeout会终止等待；unified_diff生成可审查差异；SQL问号仅绑定数据，不能代替查询结构白名单。

## 判断与排错

| 修复声明与实际不符 | 没有运行真实测试 | 在受限工作空间执行固定测试并检查退出码 |
| 参数列表仍不安全 | 调用对象是任意不可信脚本 | 区分避免shell注入和OS沙箱 |
| 只读查询泄漏租户 | 忽略查询WHERE范围 | 强制tenant与限定报告模板 |

## 工程边界

默认只执行课程自写且已审查的固定脚本，绝不接受任意模型代码。这是受控编码循环教具，不是生产执行沙箱；生产可使用无网络、只读挂载、资源限制的隔离服务，见integrations说明。

## 复习问题

交付补丁差异、实际测试结果和只读报告；解释-I为何不是安全沙箱；验证非法报告和跨范围修改失败。

## Java联系与行为边界

与Java用ProcessBuilder传参数列表相似，subprocess避免shell解释但不提供沙箱。SQLite问号与PreparedStatement一样绑定值，不能替代表权限、租户范围和SQL结构限制。

- 固定错误程序先通过真实子进程测试呈现失败。
- patch解析目标位置并只接受calc.py与批准旧内容，生成审查差异。
- 补丁完成后重新运行实际测试，退出码为0才报告通过。
- 默认只执行课程固定已审查代码，不接收任意模型生成shell命令。
- 数据报告由枚举映射到固定SQL，tenant用参数绑定，query_only作为第二道边界。
