## 1. 业务场景

只记录Git版本还不够。模型、提示词、工具Schema和知识索引都可能变，必须记录一次任务所用的完整配置，并防止质量回退。

## 2. 学习目标与前置知识

真正先修是Python基础、工具契约和状态/失败边界（对应阶段03—16）。本课不要求先完成30—38多Agent；可使用阶段39之后的服务或本地固定数据练习治理机制。按[项目里程碑](../../docs/milestones.md)持续把案例、权限、轨迹和发布记录合入主项目。

## 3. 关键概念

### 1. 版本包与配置指纹

一个发布包绑定代码、模型标识、提示词、工具Schema和索引版本。稳定JSON与摘要生成指纹便于比较，但摘要不能自动证明内容安全。

### 2. 发布门槛与灰度

候选版本必须通过固定评估与硬性安全约束。灰度逐步放量，在较小范围观察质量、错误和成本，再决定扩大。离线比较不能代替上线监控。

### 3. 回滚与旧任务

回滚恢复已验证版本；长期任务应继续绑定启动版本，不能被当前别名悄悄改变。Java发布中兼容数据库迁移的原则同样适用，代码回滚不一定能撤销数据变更。

## 4. 操作演示

默认案例使用 Python 标准库，固定本地数据，无需网络和模型密钥。以下命令从项目根目录运行：

## 5. 代码执行过程与新语法

校验版本包所有必需字段，按稳定JSON计算摘要；发布时先检查安全与成功率；只有通过才改变活动别名；任务保存启动指纹，回滚不会改变已经启动的任务。

### 本课语法提示

`{**bundle, "prompt": "v2"}`复制字典并覆盖字段；SHA256生成摘要；sort_keys保证字段顺序变化不会改变指纹。

函数的参数表示需要提供的信息，返回值表示结果。异常表示当前调用不能继续，不能简单吞掉所有异常；需要将失败类别传给上层处理。注释与讲义共同解释关键决策。

## 6. 常见错误与排查

| 症状 | 原因 | 排查与修复 |
| --- | --- | --- |
| 任务重启后行为变了 | 读取最新提示词而不是绑定版本 | 保存任务的完整版本包 |
| Git回滚仍错误 | 索引或Schema没有一起回滚 | 管理兼容的完整配置版本 |
| 安全回退仍发布 | 只看总成功率 | 安全失败设置硬门槛 |

排查时保留输入类别、状态与错误码；涉及身份、密钥和业务数据时，先脱敏再记录。一次运行成功只能证明当前案例，必须覆盖变化后的需求和失败路径。

## 源码分段追踪与Java对照

### 输入和初始化

完整bundle包含code、model、prompt、tool_schema、index五类版本。

Git只记录源码，无法自动证明模型或索引版本固定。

fingerprint先检查字段集合，缺字段或多字段都拒绝。

每个版本值需非空字符串，不把None当有效版本。

JSON排序与固定分隔符使同一bundle产生稳定字节串。

### 校验与状态推进

SHA256摘要成为完整行为版本ID，不是安全签名或模型embedding。

promote先计算候选摘要，再检查质量和安全指标。

指标未达标时抛ValueError，registry任何字段都不改。

版本包存入versions时做dict复制，防止调用方之后修改原bundle。

active是新任务使用的活动别名，不是运行中任务实时追踪字段。

task在启动时保存old版本ID，新版发布不修改task。

参考答案分别演示总体分不足和安全违规两种坏发布。

坏版本不进入versions，旧active仍指向old。

### 失败与验证证据

第二个有效版本只改prompt，摘要仍发生变化。

rollback只能选择已经登记的版本，未知ID拒绝。

回滚改变活动别名，不删除已存在的新版本或旧任务。

业务表迁移和外部副作用不能通过切换active恢复。

CI课程验证步骤运行离线演示、答案与回归测试，不请求模型密钥。

生产审批另查权限范围、索引内容、迁移兼容性、回滚与成本变化。

本课内存registry重启后丢失；生产版本目录应持久存储并保留审计。

### Java Web迁移

bundle类似Java服务部署的镜像、配置、模型及索引清单；Git commit仅是其中一项。运行任务固定版本类似保存不可变配置快照，切换active别名不能等同数据库迁移回滚。
