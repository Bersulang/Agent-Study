# 阶段 53 知识：多 Agent 调研助手项目

[返回讲义](README.md) · [全局知识手册](../../docs/knowledge.md)

### 1. 研究问题与子任务

先明确需要回答的事实和报告范围，再拆分检索任务。不能把“全面调研”当成无限搜索授权。主管设定来源范围、调用预算与结束条件。

### 2. 证据链与事实归纳

每个事实关联来源ID和具体字段；推断单独标注。来源的可信度、更新时间和适用范围都影响结论；多个来源重复转述不等于多个独立证据。

### 3. 冲突与报告检查

两个有效政策对同一字段给出不同值时，停止确定回答并要求确认版本。审查Agent核查来源是否存在和事实是否匹配，而不只修改语言。

## 执行过程

主管将按资料ID取证任务交给线程池；每个检索员返回结构化资料；核查器按事实键汇总值与来源；有冲突输出needs_review，无冲突才形成带来源的事实表。结果按来源ID排序，避免并行返回顺序影响答案。

## 新语法

`pool.map`并行调用但按输入顺序取结果；set去重；setdefault首次创建事实列表；嵌套f-string只用于报告格式，不用于SQL或shell拼接。

## 判断与排错

| 报告看起来完整却无来源 | 先生成结论再补引用 | 先建证据表再生成报告 |
| 搜索一直继续 | 没有预算和结束条件 | 限制任务数，证据不足时明确结果 |
| 冲突政策被平均 | 把相互矛盾数据直接汇总 | 确认版本与范围，必要时人工核实 |

## 工程边界

默认研究员是确定性代码，来源是明确标注的教学夹具，不是实时网页或真实企业政策。真实项目替换为搜索工具与模型节点，保留同一证据契约、引用核验、网页注入防护和总预算。

## 复习问题

提交研究任务、证据表、冲突案例和最终报告；解释事实、来源和推断区别；证明不会无限研究。

## Java联系与行为边界

Java CompletableFuture与Python线程池都可并行调用只读任务；共享预算与结果契约仍需自己设计。pool.map按输入顺序获取结果，不代表调用串行。

- source_ids去重并排序，使重复文档不会增加独立证据数量。
- retrieve验证来源存在和active状态；过期资料不进入证据表。
- 不同工作单元返回同一数据契约，汇总器按事实键组织来源和值。
- 同一事实出现不同值，标记needs_review，不能让报告生成器自行平均。
- report只在ready状态生成带来源文本；实际来源接入必须保留注入防护和来源核验。
