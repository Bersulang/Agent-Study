## 1. 业务场景

助手要总结工单处理政策，并指出不同资料之间的冲突。我们用预先准备的教学资料模拟检索，明确每个结论的来源，再把检索、核查和报告分工。

## 2. 学习目标与前置知识

先完成前面的 Python、工具、状态和协作基础。本课重点是理解机制，能够修改并验证代码。遇到不理解的语法先查看本课语法说明，再回到基础阶段复习。

## 3. 关键概念

### 1. 研究问题与子任务

先明确需要回答的事实和报告范围，再拆分检索任务。不能把“全面调研”当成无限搜索授权。主管设定来源范围、调用预算与结束条件。

### 2. 证据链与事实归纳

每个事实关联来源ID和具体字段；推断单独标注。来源的可信度、更新时间和适用范围都影响结论；多个来源重复转述不等于多个独立证据。

### 3. 冲突与报告检查

两个有效政策对同一字段给出不同值时，停止确定回答并要求确认版本。审查Agent核查来源是否存在和事实是否匹配，而不只修改语言。

## 5. 代码执行过程与新语法

主管将按资料ID取证任务交给线程池；每个检索员返回结构化资料；核查器按事实键汇总值与来源；有冲突输出needs_review，无冲突才形成带来源的事实表。结果按来源ID排序，避免并行返回顺序影响答案。

### 本课语法提示

`pool.map`并行调用但按输入顺序取结果；set去重；setdefault首次创建事实列表；嵌套f-string只用于报告格式，不用于SQL或shell拼接。

函数的参数表示需要提供的信息，返回值表示结果。异常表示当前调用不能继续，不能简单吞掉所有异常；需要将失败类别传给上层处理。注释与讲义共同解释关键决策。

## 6. 常见错误与排查

| 症状 | 原因 | 排查与修复 |
| --- | --- | --- |
| 报告看起来完整却无来源 | 先生成结论再补引用 | 先建证据表再生成报告 |
| 搜索一直继续 | 没有预算和结束条件 | 限制任务数，证据不足时明确结果 |
| 冲突政策被平均 | 把相互矛盾数据直接汇总 | 确认版本与范围，必要时人工核实 |

排查时保留输入类别、状态与错误码；涉及身份、密钥和业务数据时，先脱敏再记录。一次运行成功只能证明当前案例，必须覆盖变化后的需求和失败路径。

## 深入讲解：Java对照与逐段执行

Java CompletableFuture与Python线程池都可并行调用只读任务；共享预算与结果契约仍需自己设计。pool.map按输入顺序获取结果，不代表调用串行。

1. source_ids去重并排序，使重复文档不会增加独立证据数量。
2. retrieve验证来源存在和active状态；过期资料不进入证据表。
3. 不同工作单元返回同一数据契约，汇总器按事实键组织来源和值。
4. 同一事实出现不同值，标记needs_review，不能让报告生成器自行平均。
5. report只在ready状态生成带来源文本；实际来源接入必须保留注入防护和来源核验。

请在对应函数设置断点，分别输入成功和失败数据，观察哪一步改变状态、哪一步拒绝请求。不要只根据最终文本判断成功。
