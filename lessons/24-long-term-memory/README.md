## 概念：记忆先要有授权、归属和失效边界

跨会话保存的信息会影响未来回答，所以不能把模型猜测当作用户同意。`put`要求显式`consent`，并用`(user, key)`作为复合键；用户身份由调用方提供，不能从记忆内容反推。读取时还检查过期时间，`now >= expires`即返回None；忘记操作只删除对应用户的那项记忆。

下面摘录或简化本课示例的关键步骤，需结合[完整源码](examples/demo.py)中的定义与上下文阅读；运行时使用下方演示命令。

```python
memory.put("u1", "language", "中文", "用户明确请求", 10, True)
print(memory.get("u1", "language", 1))
print(memory.get("u2", "language", 1))
```

第一条读取“中文”，第二条是None：相同key不会让u2读到u1的数据。若在时间10读取，条件`now >= expires`成立，也得到None。过期控制的是可见性；`forget`会移除保存记录。

<details><summary>展开推导：u1授权保存后，u2读取相同key；随后u1撤回并忘记，再次读取会怎样？</summary>

第一次u2读取用键`("u2", "language")`，与`("u1", "language")`不同，因此是None。执行`forget("u1", "language")`后，u1对应条目被移除，u1再次读取也为None。若`consent=False`，`put`在写字典前抛PermissionError，旧数据不会被覆盖。
</details>

Java对照：数据库主键至少要包含用户或租户边界，查询也必须始终附带该边界；只在返回前过滤会留下越权缓存风险。生产系统还需记录同意来源、撤回审计和持久化删除范围，本课的内存字典无法证明这些行为。

### 预期输出如何阅读

第一行是u1读取自己明确保存的中文偏好。第二行u2使用不同复合键，因此读不到u1的数据；删除(u1, language)后第三行也为None。Memory在内存中，重启后数据不会保留。

## 执行过程与状态变化

1. 带授权写入复合键。
2. 查询时检查用户和失效时间。
3. 同键写入替代旧值。
4. 删除幂等，重复删除不会报错。

正常输出依次是u1读取到中文、u2读取为None、u1删除后再读为None。这个顺序展示了用户隔离与显式撤销；同键新值会覆盖旧值，但正式系统可能需要保留审计版本。

## 逐行阅读与Python语法

`put`覆盖复合键只会更新当前用户的同一项；`get`过期返回None但不会自动删除审计行；`forget`才移除内存记录。`source`保留用户明确授权的来历，不能用它代替认证用户身份。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `(user, key)` | 元组可以作为字典键；按用户与偏好联合查找，不让u2读到u1语言偏好。 |
| `consent检查` | 写入前检查同意，拒绝时旧值保持不变；真实身份和同意记录不能由模型自行编造。 |
| `expires` | 本例用整数模拟时间；生产使用明确时区的时间戳并统一时钟。 |
| `now >= expires` | 边界时刻即过期；None表示不可使用，并非值为空字符串。 |
| `put替换` | 同用户同键后写覆盖旧偏好；业务重要记忆还需保留审计历史而非只保存最后值。 |
| `pop(..., None)` | 删除不存在键返回None，重复撤销仍安全。 |
| `提取边界` | 聊天提到同事喜欢英文不代表当前用户偏好；只有明确可归属、必要且授权的事实才进入记忆。 |

## Java Web对照

Java可用不可变复合键record表达(user,key)；需要让equals/hashCode都包含两个字段，才能保持与本课租户隔离一致。

## 易错点与排错顺序

1. 文件路径错误：确认终端在项目根目录，先运行演示而不是练习骨架。
2. 把空结果当成功：查返回状态与来源，不能编造缺失字段或证据。
3. 在失败后继续修改：先验证再变更，给失败输入补行为测试。
4. 共享可变对象：调用前后打印输入，确认是否被无意修改。
5. 把模拟效果当生产质量：检查本页边界说明与真实接入目录。
6. 只看最终回答：保留查询、状态或执行轨迹，定位失败发生在哪一步。
