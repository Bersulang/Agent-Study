# 阶段 25：工作空间与任务恢复

## 使用场景

生成报告中途停止，恢复时复用已经完成的阶段，但文件只能写在授权工作空间。

主线项目是企业知识与工单协作助手。本阶段只增加一个可解释的能力边界，先验证机制，再讨论规模化。
运行演示不需要模型密钥，也不会请求真实业务系统。

## 学习目标

- 能用摘要检查恢复产物完整性，并拒绝损坏状态而非静默覆盖。

## 概念：检查点必须晚于产物，恢复必须核对两者

长任务可能在任意一步退出。恢复时不能只看到`stage == "done"`就相信任务完成：报告文件可能被删除，也可能在上次写入时只写了一半。本课的`resume`先检查工作空间里的`checkpoint.json`，再看`report.json`是否存在；只有完成标记和产物同时存在才返回`reused`。

下面摘录或简化本课示例的关键步骤，需结合[完整源码](examples/demo.py)中的定义与上下文阅读；运行时使用下方演示命令。

```python
report.write_text(report_text, encoding="utf-8")
checkpoint.write_text(json.dumps({"stage": "done"}), encoding="utf-8")
```

顺序是关键：先落报告，再写完成状态。若反过来，进程可能在“checkpoint已完成、报告尚未写出”之间崩溃。只信完成标记的恢复逻辑会误报成功；本例额外检查报告存在性，遇到缺失会重新生成，但仍不能识别存在却只写了一半的报告。演示中第一次运行没有检查点，于是生成报告后记录`done`并返回`created`；第二次运行两者都在，返回`reused`。

路径检查与恢复检查解决不同问题。`safe_path`将根路径和相对路径都解析成规范路径，再以`is_relative_to`确认目标仍在根目录下；这能拒绝`../outside.txt`一类逃逸路径。仅靠字符串前缀会把`workspace-old`误认成`workspace`的子目录。即使路径检查通过，进程仍可能在检查后遇到符号链接被替换的竞态，因此生产环境还要用目录权限、原子替换和并发控制。

<details><summary>展开推导：checkpoint写着done，但report.json不存在，下一次应返回什么？</summary>

不能复用。`done`只说明状态文件曾记录完成，缺少报告意味着结果当前不可用；本演示会重新生成报告、写入完成状态并返回`created`。若checkpoint是损坏JSON，解析会失败而不是默默覆盖，因为覆盖会丢掉定位上次中断原因的证据。
</details>

Java对照：`Path.toRealPath`或规范化路径检查可以帮助确认目录边界，但字符串`startsWith`仍有同前缀目录问题。数据库事务中的状态与业务数据可以原子提交；两个普通文件没有这样的事务，本例“先报告、后检查点”只降低错误窗口，不能保证并发或崩溃下原子性。

### 默认演示预期输出

```text
created
reused
```

### 预期输出如何阅读

第一次调用创建report.json后写入done检查点，返回created；第二次检查到done和报告都存在，返回reused。它只验证存在状态；练习要求再比对SHA256，才能知道产物内容未被改动。

## 执行过程与状态变化

1. 在临时目录建立工作空间。
2. 检查现有状态和报告存在性。
3. 缺失产物时重新生成再保存检查点。
4. 第二次调用复用完成结果。

默认入口用TemporaryDirectory创建隔离目录，第一次返回created，第二次因done和report均存在而返回reused；离开with作用域后临时目录自动清理。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `Path(root).resolve()` | 变成绝对规范路径，处理..和已存在链接，不能只用字符串startswith比较。 |
| `is_relative_to(base)` | 检查真实路径是否在工作空间下；同前缀的相邻目录不会被误认为子目录。 |
| `checkpoint.exists()` | 有检查点才读取；坏JSON会明确失败，本例不把损坏证据覆盖成new。 |
| `done与report.exists()` | 状态完成且产物存在才复用；只有done但文件丢失要重建。 |
| `write_text的顺序` | 先产物后状态，减小状态超前风险，但两文件仍非原子事务。 |
| `TemporaryDirectory` | with离开自动清理；默认演示不会把测试报告留在业务目录。 |
| `恢复升级` | 生产写临时文件后原子替换检查点，用摘要核验产物，并发任务要有锁；路径校验还需OS沙箱防竞争攻击。 |

## Java Web对照

Java的Path.normalize/realPath可做路径检查，但字符串前缀同样不够；文件系统竞态需用操作系统权限和安全打开方式处理。

## 易错点与排错顺序

1. 文件路径错误：确认终端在项目根目录，先运行演示而不是练习骨架。
2. 把空结果当成功：查返回状态与来源，不能编造缺失字段或证据。
3. 在失败后继续修改：先验证再变更，给失败输入补行为测试。
4. 共享可变对象：调用前后打印输入，确认是否被无意修改。
5. 把模拟效果当生产质量：检查本页边界说明与真实接入目录。
6. 只看最终回答：保留查询、状态或执行轨迹，定位失败发生在哪一步。

## 工程延伸与边界

普通文件检查点不是事务；本例无并发保护，路径校验不是操作系统沙箱。生产需原子替换、文件锁与进程权限约束。

从本课迁移到企业项目时，先写输入输出契约与独立评估案例，再决定存储、模型和框架。

单元测试覆盖本地规则；真实网络、持久化、并发与供应商行为需要额外集成验证。
