# 阶段 26：按需加载的能力包

## 使用场景

报表能力包含说明、模板和脚本，系统应先发现再按需读取，执行仍需要权限。

主线项目是企业知识与工单协作助手。本阶段只增加一个可解释的能力边界，先验证机制，再讨论规模化。
运行演示不需要模型密钥，也不会请求真实业务系统。

- 能说明技能文本不能替代工具参数校验与执行沙箱。

## 概念：发现能力与授予能力是两件事

技能清单可以按任务文字发现候选，但被发现不代表获准执行。`discover`只看trigger并返回名字；`load`再确认名字存在、检查权限，最后返回元数据副本。这样模型可以提出“需要清理”，程序仍能在缺少delete权限时拒绝加载。

下面摘录或简化本课示例的关键步骤，需结合[完整源码](examples/demo.py)中的定义与上下文阅读；运行时使用下方演示命令。

```python
names = discover("生成工单报告")
print(names)                       # ['report']
print(load(names[0], {"read"}))    # 读取技能元数据
```

`cleanup`触发词是“清理”，需要delete权限；用只有read的权限集加载它会抛PermissionError。技能中的instructions只是文本说明，本演示没有执行其中代码，也没有为技能授予系统级权限。

<details><summary>展开推导：任务命中“清理”，当前权限只有read，程序会执行清理说明吗？</summary>

`discover`会返回cleanup，因为触发词命中；随后`load("cleanup", {"read"})`发现所需delete不在权限集合中并抛PermissionError，instructions不会返回给后续执行器。生产系统还应在每个具体工具调用处再次授权，不能把技能描述当成权限令牌。
</details>

Java对照：可将技能元数据视为版本化配置或服务注册表中的能力声明；实际操作仍经授权的Service方法执行。动态加载脚本会增加供应链风险，本课只复制字典元数据，不导入插件代码。

### 默认演示预期输出

```text
['report']
{'version': '1.0', 'trigger': '报告', 'permission': 'read', 'instructions': '读取工单；汇总数量；使用中文模板；标注来源。'}
```

### 预期输出如何阅读

discover只返回匹配trigger的report名称；load随后读取version、read权限和instructions。打印出说明不表示已经执行报告，也不表示获得delete权限；清理能力仍需要调用者明确具备delete。

## 执行过程与状态变化

1. 摘要匹配发现report。
2. 使用可信权限集合检查能力。
3. 复制详细说明避免修改注册表。
4. 返回版本化包内容，后续执行仍受工具层约束。

输出先列出命中的report，再显示其版本、触发词、read权限和说明。这表示技能被找到并加载，不表示其中步骤已执行或真实业务权限已授予。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `discover只看trigger` | 摘要用于发现；未命中时不载入长说明，节省上下文容量。 |
| `permissions集合` | 权限来自宿主的可信上下文；不能因为任务含清理两个字就自动取得delete权。 |
| `name not in SKILLS` | 未知能力包明确失败，不能运行任意同名文件或用户输入路径。 |
| `dict(meta)` | 返回副本，修改加载结果不会悄悄改变注册表版本。 |
| `instructions字段` | 文本说明提供步骤，不能绕过工具层参数校验；技能本身不是安全沙箱。 |
| `resources/report` | 真实能力包样本含SKILL.md和template.md；版本固定1.0，可对照正例与负例。 |
| `版本演化` | 新版本增加脚本或写权限时需重查执行边界；旧任务恢复时不能静默使用语义不同的新步骤。 |

## 易错点与排错顺序

1. 文件路径错误：确认终端在项目根目录，先运行演示而不是练习骨架。
2. 把空结果当成功：查返回状态与来源，不能编造缺失字段或证据。
3. 在失败后继续修改：先验证再变更，给失败输入补行为测试。
4. 共享可变对象：调用前后打印输入，确认是否被无意修改。
5. 把模拟效果当生产质量：检查本页边界说明与真实接入目录。
6. 只看最终回答：保留查询、状态或执行轨迹，定位失败发生在哪一步。

## 工程延伸与边界

真实包样本位于resources/report：SKILL.md说明触发与权限，template.md组织报告，scripts/summarize.py统计已授权输入。
从项目根目录执行 `python lessons/26-skills/resources/report/scripts/summarize.py`，正常输出open=1、closed=1并记录T3缺失状态；不填参数使用离线夹具。
脚本属于能力包资源，读取说明不等于允许执行；宿主仍需决定调用权限与数据来源。

SKILL.md格式依赖宿主实现；本例是能力包机制演示，不是任何具体产品的完整加载器，也不执行不可信脚本。

从本课迁移到企业项目时，先写输入输出契约与独立评估案例，再决定存储、模型和框架。
保留可追溯来源和任务/身份信息，让问题能定位到具体数据与步骤。
添加性能优化前先检查正确性，尤其是失败时是否仍保护权限、预算和有效状态。
单元测试覆盖本地规则；真实网络、持久化、并发与供应商行为需要额外集成验证。
