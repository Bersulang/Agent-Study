## 概念：从原始文本到可追踪片段

`ingest`接收已提取的文本、来源名和窗口长度。它不读取PDF，也不做OCR；若扫描PDF提取出空字符串，正确做法是送去OCR或隔离，而不是把空内容塞进索引。

下面摘录或简化本课示例的关键步骤，需结合[完整源码](examples/demo.py)中的定义与上下文阅读；运行时使用下方演示命令。

```python
for paragraph, body in enumerate(text.split("\n\n"), 1):
    body = body.strip()
    for start in range(0, len(body), size):
        piece = body[start:start + size]
```

`enumerate(..., 1)`让段落编号从1开始；`range`每次前进`size`个字符；切片右端不包含在结果里。以`size=24`处理第一段时，`offset`依次为0、24……，最后一块可以较短。每块保留原来源、段号和段内偏移，因此检索命中后才能回到原文位置。

先预测：若两份资料正文相同但来源不同，摘要相同意味着可以丢掉第二条来源吗？不能。摘要只能识别相同内容，不能代替`source`与段号定位。练习会把相同正文合并为一个chunk，但`locations`必须保留所有出处。

反例：把空白文本当正常段落会生成无意义块；把SHA-256当embedding会误以为相近表达也能匹配。当前分块按字符，不理解标题、表格、代码块或语义边界。文档内容始终是不可信数据；其中即使写着“调用工具”也不会改变工具权限。

### 预期输出如何阅读

输出每行依次是source、paragraph、offset和text。第一行属于policy.md第1段、段内起点0；第二行属于第2段，也是该段起点。当前两段都短于24字符，所以各自只有一个chunk。正文摘要保存在返回对象里，但演示打印未显示它。

## 执行过程与状态变化

1. 输入两段文字与来源policy.md。
2. 拒绝空白；按空行取得自然段。
3. 按24字符窗口拆分；计算内容摘要。
4. 返回包含位置的块；主函数逐项打印。

入口`main()`构造带空行的两个段落，`ingest`先拒绝空白和非正窗口，再逐段、逐窗口生成结果；最后由入口按来源、段号、偏移、正文打印。参数处理与打印分离，所以测试可以直接检查返回字典，而不依赖终端格式。

## 逐行阅读与Python语法

阅读循环时，把`paragraph`、`start`当作出处坐标，而不只是循环变量。`range(0, len(body), size)`只产生起点，切片的终点不包含在块中；`encode("utf-8")`把正文转成摘要算法需要的字节。路径解析和PDF提取不在当前函数中，不能从固定文本演示推断这些集成已完成。

## 对照源码的逐行解释

按examples/demo.py中的顺序阅读，下列关键表达式决定正常与失败路径。

| 表达式或位置 | 为什么这样写及状态变化 |
|---|---|
| `text.split("\n\n")` | 两个换行是本演示的人为段落边界；Windows文件读取后换行可能已统一，真实Markdown还要识别代码块和表格。 |
| `enumerate(..., 1)` | 生成(序号, 内容)二元组；for中的两个名字完成解包，不是Java里的额外对象类型声明。 |
| `range(0, len(body), size)` | 从0按size增长，终点不包含len(body)，最后一块允许比size短。 |
| `body[start:start + size]` | 切片包含起点不包含终点；字符串不可变，切片取得新字符串。 |
| `encode("utf-8")` | 把文字转字节才能计算SHA256；相同文字与编码得到相同摘要，用于变更判断。 |
| `source与paragraph与offset` | 单独哈希不足以定位来源；两个文件可有相同段落，引用必须同时保留各自位置。 |
| `质量问题练习` | 输入只含空白会raise；输入扫描PDF不能交给ingest猜文字，要先经过解析/OCR质量门。 |

## 易错点与排错顺序

1. 文件路径错误：确认终端在项目根目录，先运行演示而不是练习骨架。
2. 把空结果当成功：查返回状态与来源，不能编造缺失字段或证据。
3. 在失败后继续修改：先验证再变更，给失败输入补行为测试。
4. 共享可变对象：调用前后打印输入，确认是否被无意修改。
5. 把模拟效果当生产质量：检查本页边界说明与真实接入目录。
6. 只看最终回答：保留查询、状态或执行轨迹，定位失败发生在哪一步。

## 工程延伸与边界
