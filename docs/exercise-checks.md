# 练习自动校验与进度记录

每课先读讲义、运行演示，再独立修改 `exercises/` 内的练习。完成后运行对应阶段的校验命令，无需手工粘贴命令输出或填写提交表。

## 从阶段01开始

以下命令在项目根目录的PowerShell中运行：

```powershell
.\.venv\Scripts\python.exe tools/check_exercise.py 01
```

`01`是阶段编号。阶段02用`02`，后续依此类推到`56`。不需要激活虚拟环境或安装第三方依赖。

校验会逐项输出“通过”或“未通过”，失败时附实际异常或不符合要求的原因。按提示修改练习、保存文件，再运行同一命令。脚本退出码0表示本次代码检查通过，1表示练习尚未通过，2表示检查或记录环境出错。尚未实现的骨架不能通过。

以阶段01为例，你只需独立完成启动卡片的四行输出和中文注释，然后执行命令。助手名称可自行选择；检查关注要求，不要求和参考答案逐字相同。运行检查不会替你填写卡片。

## 哪些内容会自动保存

- [学习进度](progress.md)：自动更新对应阶段的练习列及页面末尾的检查记录。
- `.local/exercise-progress.json`：保存每项结果、UTC检查时间和代码指纹，是自动状态的事实来源。首次运行时生成，不需要预先创建；属于需要保留的学习数据，不作为临时文件清理。
- `artifacts/exercise-checks/NN-latest.json`：最后一次详细报告，可用于排错，不需要你手写。

通过后显示“代码校验通过”；未通过显示“待修改”。重新执行失败会覆盖旧的通过状态，不会继续显示已通过。

查看当前状态：

```powershell
.\.venv\Scripts\python.exe tools/check_exercise.py --status
```

此命令也会比较当前作业和规则的指纹。通过后修改了练习、相关示例或检查规则，会显示“代码或规则已变化，待重验”，需要再次运行对应阶段命令。文件保存本身不会自动触发后台检查；在运行校验或查看状态时刷新记录。

## 自动通过的范围

检查器使用明确输入、预期输出、状态和错误条件检查学员代码。开放任务采用各课练习页说明的自动校验接口；你可以组织自己的实现，再通过该接口连接检查器。

“代码校验通过”表示满足已列出的本地行为检查。它不等于已经理解全部概念，也不证明真实模型质量、真实服务、部署或企业负载已通过。概念疑问可直接在对话中解释与验收，无需另填表；真实集成仍按[集成关卡](integrations.md)记录。学习当前阶段和完整能力状态不会被本地测试擅自推进。

检查器运行你自己写的Python代码，设有子进程超时；它不是文件/网络权限沙箱。练习使用课程固定数据或临时目录，不要自行调用生产系统或付费模型。

## 与课程材料验证的区别

`tools/verify_course.py`是材料维护命令，会运行课程示例、骨架和参考答案；它不能给学员作业判分。

`tools/check_exercise.py NN`才是你的练习校验命令，它调用`exercises/`中的实现，不把参考答案或演示测试通过当成作业通过。

维护者检查材料时使用：

```powershell
.\.venv\Scripts\python.exe tools/check_exercise.py 01 --no-record
```

`--no-record`只显示检查结果，不更新你的进度。验证检查器所用的合格样例放在临时目录，不能写进学员练习或当成学员提交。

阶段01开放表达规则：依次填写名称、用途、当前能力和下一步目标，但输出不必包含这些标签，也不限制名称或具体规划。自动检查四条非空输出、明显模板占位、重复内容和中文注释；不声称能判断自然语言含义。内容是否贴合题意可在学习对话中讨论，不作为关键词匹配的通过条件。

## 所有阶段的开放题原则

解释、摘要、回答和设计理由不以固定关键词或与参考答案逐字相等来判分；自动检查只证明明确约定的结构与行为。业务结果对象允许附加说明字段（题目明确禁止未知输入字段的Schema除外）。协议字段、状态码、输入事实、排序、权限、预算与幂等约束属于固定契约，不因开放表达而放宽。内部实现可以自由组织，通过每课说明的函数接口提供验收结果。

阶段13检查结构化工具观测，不通过回答中是否出现closed或None判断业务成功；阶段23允许独立source字段及自定义证据标识；阶段02、17、18、35、41、53接受不改变必需业务字段的附加诊断信息。阶段09的access/billing/unknown是明确分类标签，不是要求照抄提示词。后期项目的报告与方案不以固定措辞打分，自动检查仅覆盖各课列出的代码子集。
