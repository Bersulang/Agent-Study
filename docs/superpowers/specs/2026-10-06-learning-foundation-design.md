# Agent 工程学习项目：第一批内容设计

## 需求来源

用户已确定 56 个能力阶段的学习方向，并要求开始内容落地，在项目内持续维护知识文档。Python 按初学者讲解，利用已有 Java Web 经验，复杂代码充分注释，按能力验收而非时间推进。

## 本批交付

- 保存完整 56 阶段路线，保留学习内容与能力验收。
- 建立课程入口、教学约定、知识文档和学习进度。
- 完整交付阶段 01：解释器、终端、虚拟环境、依赖、脚本运行、编辑器、断点和 Git 入门。
- 提供最小可运行示例、独立练习和参考答案。
- 在用户环境运行示例、检查 Markdown 链接，并核实虚拟环境解释器。

## 教学结构

采用业务场景 → 学习目标 → 概念 → 演示 → 逐行解释 → 易错点 → 独立练习 → 验收的结构。参考案例驱动的教学组织方式，讲义和代码自行编写。正文首次出现术语须解释；新语法不默认已掌握。

## 文件职责

- `README.md`：学习入口和第一步。
- `AGENTS.md`：后续协作者维护约定。
- `docs/roadmap.md`：56 阶段全局路线。
- `docs/teaching-guide.md`：教学与注释规范。
- `docs/knowledge.md`：持续更新的知识手册。
- `docs/progress.md`：材料、练习和验收状态。
- `lessons/01-environment/README.md`：第一阶段完整讲义。
- 同目录 `examples/`、`exercises/`、`solutions/`：演示、学员练习和参考答案。

## 实施约束

Windows PowerShell；基线 Python 3.12；本阶段仅使用标准库；不安装第三方包，不调用付费模型。虚拟环境直接指定解释器运行，激活作为可选知识。脚本不读取凭证、不访问网络、不写业务数据。

## 验收与边界

代码运行验证只证明课程材料可用，不证明学员掌握。仅将阶段 01 标为材料已准备，所有学习能力仍待验收。后续阶段只保存路线，不声称已经制作完整课程。

当前目录为空且没有 Git 仓库，在用户指定目录原地创建课程文件；不创建隔离工作树、不提交、不推送。阶段 01 是低影响教学脚本，采用实际运行与语法检查验证，不引入重复实现的自动化测试。
