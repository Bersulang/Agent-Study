# 全部 56 阶段课程交付设计

## 用户授权

用户要求完成全部阶段内容，并记录一次 Git 提交，提交描述为“初始化工程”，后续自行维护远程仓库。本次只创建本地仓库和提交，不创建或推送远程。

## 完整性交付标准

保留阶段 01 和既有 56 阶段编号。阶段 02—56 各自交付完整讲义、注释演示、独立练习、参考答案和验收标准，配套知识文档。不得只创建标题或待补充大纲。

每课必须解释场景、目标、前置知识、至少三个关键概念（定义、用途、具体例子）、代码执行过程、常见错误、独立练习、验收与工程延伸。Python 新语法说明；使用 Java 对照但指出差异。后续 API/框架资料引用官方来源。

## 可运行性与真实接入

默认案例使用标准库和确定性本地数据，可无密钥、无网络运行。模拟模型、哈希向量、内存队列、协议子集等必须明示教学边界，不能冒充真实 SDK、生产沙箱或完整协议。

LangGraph、MCP、FastAPI、外部模型、Java 服务等章节提供实际接入代码或可执行工程文件与安装/启动命令；区分离线演示和需要外部环境的集成。缺少密钥和外部环境时，只报告已执行的离线验证和导入/本地接口验证，不能声称真实服务通过。

## 文件约定

- `lessons/NN-topic/README.md`：完整教学内容。
- 同阶段 `examples/demo.py`：默认离线演示；复杂案例允许模块化。
- `exercises/practice.py`：可运行练习骨架，不预填最终答案。
- `exercises/README.md`：独立需求和验收题。
- `solutions/solution.py`：完整参考实现，中文注释。
- `tests/test_*.py`：涉及有意义行为的回归测试，标准库 unittest 优先。
- `knowledge.md`：该阶段详细知识，根知识手册链接到此。
- `integrations/`：真实 SDK、HTTP、服务和部署示例。

直接执行命令一律以项目根目录为工作目录，解释所需依赖。默认演示和答案执行应有限、无外网、无凭证、无常驻服务；写入结果放 `artifacts/` 或临时目录。

## 并行边界

按阶段 02—16、17—29、30—43、44—56 分区；各分区只修改自己的阶段目录。根代理维护共享文档、配置、课程目录、验证脚本和 Git。子代理不提交、不更新共享进度。

## 验证和提交

逐个运行默认演示与答案，检查全部 Python 语法、阶段内容与链接，执行相关测试并审查典型高级阶段。新增自动化验证脚本支持在干净目录复现。完成后更新 README、路线、知识索引、56 阶段交付/学习状态和真实验证报告，检查忽略凭证、虚拟环境与运行产物，再使用“初始化工程”作为唯一初始提交信息。

## 学习状态

全部材料可以预先交付，但学员当前仍从阶段 01 开始，所有阶段的能力状态均待验收。
