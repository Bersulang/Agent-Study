# 企业知识与工单助手：连续项目里程碑

这五个里程碑让同一个主项目逐步增加能力。阶段编号仍用于查找课程；里程碑强调如何把课程成果接成一个可运行系统。每个阶段的小练习用于掌握局部概念，里程碑用于验证多个模块之间的接口和状态能否配合。

建议项目沿用 `projects/enterprise-assistant/` 目录，由学员自行创建和维护，不提供预填实现。可以按阶段增量组织 `src/`、`tests/`、`data/`、`docs/` 和配置模板；每次扩展前写下输入输出契约，并记录旧行为仍需成立的案例。详细代码结构由学员按阶段需求决定。

环境相关验收可先标记“机制已通过，集成待验收”。这表示已有固定数据证明控制逻辑符合预期，不表示真实集成完成或该里程碑完整通过。无依赖课程可继续学习，后续具备环境时补齐集成证据。

## 里程碑 1：Python 工单 CLI

- **关联阶段**：01—07；重点阶段 02—05。
- **前置能力**：能从项目根目录运行 Python 3.12，使用函数、模块、文件和异常处理。
- **沿用成果**：阶段 01 启动程序、阶段 02 工单字典、阶段 03 函数模块、阶段 04 JSON/文件处理、阶段 05 工单数据模型；保留原来的列表、查询和输入错误案例。
- **新增能力**：命令行查询、创建和更新本地工单，输入校验，JSON 持久化，清晰错误信息。
- **状态与接口**：定义 Ticket 的必需字段和状态枚举；命令解析层调用业务函数，业务函数调用 Repository；记录非法状态转换和损坏文件时的失败行为。
- **交付路径建议**：`projects/enterprise-assistant/` 下由学员建立 `src/`、`tests/`、`data/`、`docs/`；写明从根目录启动的命令与数据文件位置。
- **验收案例与证据**：成功查询、未知工单、非法优先级、损坏 JSON、重复创建。提交实际命令/输出、至少一个失败修复说明，以及一项现场修改后的预测和验证。

## 里程碑 2：单 Agent 反馈循环与审批

- **关联阶段**：08—16；安全、评估与追踪从本里程碑开始持续记录。
- **前置能力**：里程碑 1 的模块边界和测试习惯；阶段 11 工具契约、12 幂等与权限、13 反馈循环、16 审批绑定。
- **沿用成果**：保留 CLI 和 Repository，通过服务接口提供只读工单查询和受控写入；复用阶段 13 的消息与轨迹概念，不能把教学模拟说成真实模型能力。
- **新增能力**：模型根据工具结果选择下一步，错误时受控重试或停止；写操作形成草稿，批准绑定租户、动作和参数摘要后才执行。
- **状态与接口**：记录每轮模型决策、工具调用标识、工具观测、预算和停止原因；区分 `draft`、`pending_approval`、`approved`、`rejected`、`completed`。模型只提议动作，服务端校验权限。
- **交付路径建议**：在项目内新增 Agent/工具/审批模块和可重复测试；设置固定小型评估集，保存成功、拒绝和错误轨迹。
- **验收案例与证据**：改变工具返回值后，后续动作相应改变；未知工具、工具异常、预算耗尽会安全终止；越权写被拒绝；审批后参数变化要求重新审批；提交轨迹和权限判断证据。
- **集成关卡**：阶段 08 的真实文本模型只证明文本请求可用。要验收真实模型工具循环，必须证明模型轮次、工具调用关联 ID、工具观测回传、未知工具/失败处理、停止预算与用量记录均可追踪。可使用适配器或自有模型服务，不限定供应商 SDK。

## 里程碑 3：真实资料 RAG

- **关联阶段**：17—22。
- **前置能力**：里程碑 2 的问答入口、固定评估集、轨迹和错误呈现；阶段 17 文档解析与质量检查。
- **沿用成果**：保留原有单 Agent、权限校验、评估集和可观察轨迹；将知识检索作为受控只读工具接入，不复制出另一套问答入口。
- **新增能力**：导入真实授权资料，保存来源和版本，检索片段并给出可核查引用；无证据或资料冲突时说明限制。
- **状态与接口**：文档版本、片段来源、访问范围和索引版本与答案关联；检索接口返回证据及来源，删除/过期资料不可继续支持回答。
- **交付路径建议**：由学员选取可合法使用的小型资料集，在 `data/` 保存来源说明；把导入、检索、回答和评估命令写进项目文档。
- **验收案例与证据**：真实资料可定位引用、无证据问题拒答、过期/删除资料不再命中、跨权限资料不可见、提示注入内容不能覆盖系统指令；附检索结果和固定评估记录。
- **集成关卡**：阶段 18 至少使用一种真实 Embedding 或本地真实向量服务跑通索引和检索，并记录模型/服务版本；标准库夹具只能证明检索流程机制。

## 里程碑 4：API、持久化与业务集成

- **关联阶段**：23—29、39—43；阶段 37 A2A 为进阶分支。
- **前置能力**：单 Agent 与 RAG 的核心服务；阶段 39 服务接口前，建议完成阶段 23—25 对上下文、记忆和恢复状态的理解。阶段 37 先修阶段 39 服务基础以及 36 的协作失败处理。
- **沿用成果**：复用既有 Agent、知识和审批接口；保留其评估案例、权限边界和事件轨迹。
- **新增能力**：HTTP API、任务与会话持久化、身份透传、业务系统调用、异步 Worker、重连、幂等和重启恢复。
- **状态与接口**：明确定义 API 请求/响应、任务事件、身份上下文、审批状态、幂等键和持久化记录；要求 API/Worker 之间可追踪同一个任务。
- **交付路径建议**：沿用同一项目，在 `integrations/` 或 `deploy/` 记录外部服务启动步骤；区分离线契约测试和真实服务测试，不能为了演示在学员机器写入生产数据。
- **验收案例与证据**：合法和非法 API 请求、断线重连、身份越权、重复请求、同键不同参数、响应丢失后重放、服务重启恢复；提交接口契约、测试记录、审计/轨迹片段。
- **集成关卡**：阶段 39/40 分别验证真实 API 和 Java 服务契约；缺少 Java 环境时标记待验收。阶段 37 使用远程协议前已有 39 服务基础，属于可延后的专项集成。

## 里程碑 5：治理与毕业交付

- **关联阶段**：44—52、56；53—55 专项项目按需扩展。
- **前置能力**：里程碑 4 可运行服务、可追踪任务状态和可重放评估集；不要求先完成多 Agent 专项。
- **沿用成果**：将同一服务的需求、质量集、权限矩阵、追踪和部署流程作为治理对象；单 Agent 或工作流即可作为最终架构。
- **新增能力**：设定质量/延迟/成本阈值，持续回归，安全测试、租户隔离、部署、版本发布、回滚、备份恢复和事故处理。
- **状态与接口**：保存代码、提示词、模型、工具 Schema、知识索引版本；建立发布门槛、运行告警、恢复目标和变更记录。
- **交付路径建议**：项目根目录交付架构/需求/验收/运维文档、部署配置模板和测试评估报告；目录应能在干净环境按说明复现。具体系统由学员完成，练习骨架不替代项目成果。
- **验收矩阵与证据**：成功、无证据、越权、审批过期/撤销/参数修改后重新审批、重放、幂等冲突、重启恢复、故障定位、部署/回滚/恢复和一个未练过的新需求。质量、延迟和成本阈值由学员按业务场景预先填写，提交真实模型/服务的测量或清楚标记集成待验收。

阶段目录保留各自独立练习和参考答案。里程碑验收要检查新系统和接口演进，不能用课程示例已运行替代学员项目验收。学员当前进度见 [学习进度](progress.md)；机制与真实接入的状态约定见 [集成边界](integrations.md)。
