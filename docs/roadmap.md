# Python → 企业级 Agent：完整进阶路线

## 使用方法

12 个模块、56 个能力阶段，按掌握程度推进。阶段编号作为知识、练习与验收的关联依据。

阶段编号是稳定的课程目录，不表示每一课必须依次完成。根据项目依赖选择推荐路径，真实先修列在下方；模块外的专项阶段可按目标延后。

每阶段都包含讲义、最小示例、主项目实践、失败场景和独立验收。全部56阶段的讲义、知识、示例、练习与参考答案已交付。默认案例可离线运行；真实接入依赖、命令和验证边界在各课集成目录说明。

统一通过标准：能解释、能修改、能排错、能验证。课程材料通过运行检查不等于学员掌握。

## 项目主线

企业知识与工单协作助手从启动脚本演进为具备知识问答、业务工具、审批、多 Agent、任务恢复、权限隔离和生产治理的后端服务。开始使用模拟数据，之后接入数据库和 Spring Boot。

专项项目为多 Agent 调研助手、受限编码与数据分析助手、浏览器与多模态助手，用于验证迁移能力。

连续主项目的目录增量、接口状态和验收证据见 [五个项目里程碑](milestones.md)。阶段小练习验证局部能力，里程碑验证同一系统的集成与演进。

## 推荐路径与真实先修

- **Python基础**：01—06建立运行、数据、函数、文件、类型和异步测试能力。
- **单Agent核心服务优先**：07—16完成需求、模型调用、工具契约、反馈循环和审批。07/08开始保留评估基准；13记录决策轨迹；17开始测试检索资料中的不可信指令；第一次增加写工具时就验证权限与审批。
- **知识能力**：17—22完成导入、RAG和检索评估。真实Embedding是阶段18集成验收项，缺少模型环境可先完成机制验收并继续学习。
- **工程机制**：23—29继续上下文、恢复、框架与协议。27理解状态、审批和恢复时应复习13—16与25；28需要11的工具契约；29需要28及HTTP认证基础，可在39的对应小节后补做远程集成。
- **核心服务闭环**：先学习39—43，完成API、持久化、业务集成和可靠恢复；之后可回到37做A2A远程能力。37需先具备阶段36失败处理及阶段39服务基础。37是专项进阶，不阻塞单Agent核心交付。
- **多Agent选修深化**：30—36在完成30职责划分后学习协作模式。阶段38的架构判断可提前预习，正式对比时用同一评估集；多Agent专项不作为完成核心服务的前置。
- **持续治理**：44—52以已运行的核心服务为对象。它们不要求先完成30—38多Agent；具体前置是Python、工具与状态基础，以及可供治理的服务/任务/评估素材。评估、追踪、安全从07/08/13/17和首个写工具开始贯穿，到44—48再系统深化。
- **毕业交付**：56以单Agent或工作流均可完成；是否采用多Agent应由38的证据支持。53—55是专项迁移能力，可根据场景安排。

推荐路径只表达真实知识依赖，不代表能力自动通过。缺少外部服务时标记“机制已通过，集成待验收”，不阻塞无依赖课程；只有两类要求都通过，阶段或里程碑才算完整通过。映射见[集成边界与关卡](integrations.md)。

## 模块三：工具、单 Agent 与 Runtime

Runtime 指 Agent 的执行环境与控制机制，包括消息、状态、事件、工具、预算与生命周期。

| 阶段 | 学习内容 | 实战与能力验收 |
| --- | --- | --- |
| 11 | 工具描述、参数、结果、错误契约与工具粒度 | 实现查询工具，参数由程序校验，结果结构稳定 |
| 12 | 工具超时、重试、幂等、结果大小、权限与凭证 | 模拟失败，判断可重试条件，避免重复写入 |
| 13 | 手写模型—工具循环、ReAct、停止条件 | 完成多步任务，限制步数，处理未知工具与连续失败 |
| 14 | 消息、状态、事件、工具注册、中间件、取消和预算 | 建立最小执行器，定位当前步骤与停止原因 |
| 15 | 工作流、状态机、路由、依赖、规划与重规划 | 固定流程中加入有限动态规划，适应结果变化并正确结束 |
| 16 | 澄清、编辑、审批、拒绝、转人工、结果检查与有限修订 | 审批绑定具体动作与参数，拒绝后不执行，检查依据可核查 |

## 模块四：知识系统与 Agentic RAG

RAG 为检索增强生成；Agentic RAG 在此基础上增加受控的检索决策与迭代。

| 阶段 | 学习内容 | 实战与能力验收 |
| --- | --- | --- |
| 17 | Markdown、PDF、表格、OCR、结构、分块、元数据 | 建立导入流程，检查解析质量，保存来源与错误记录 |
| 18 | Embedding、向量检索、引用与无答案处理 | 带来源问答，引用定位真实资料，无证据时说明限制 |
| 19 | 混合检索、重排序、查询改写、过滤、召回与准确性 | 用困难问题定位检索失败、证据错误和生成误读 |
| 20 | 版本、增量更新、去重、删除、过期、索引迁移与重建 | 更新和删除政策，旧索引不继续提供失效答案 |
| 21 | 权限过滤、知识覆盖、检索评估、引用与冲突 | 加部门隔离和矛盾资料，检索不越权，冲突处理明确 |
| 22 | 检索决策、多轮检索、查询分解、证据检查、停止条件 | 实现受预算限制的检索助手，与普通 RAG 比较 |

## 模块十二：毕业交付

| 阶段 | 学习内容 | 实战与能力验收 |
| --- | --- | --- |
| 56 | 完整需求、架构、开发、测试评估、权限、部署、回滚、恢复和运维 | 独立交付企业助手，新增未练过的需求，能够解释取舍并维护系统 |

毕业交付包括需求和成功标准、架构决策、代码与注释、接口、知识与工具设计、状态与权限设计、测试与评估报告、部署与故障处理手册。

质量、延迟和成本阈值根据具体任务、负载和预算事先约定。检验无证据处理、权限与审批、租户隔离、幂等与恢复、变更回归、故障定位和独立扩展能力，不宣称适用于所有企业场景。

## 选修范围

Transformer 深入原理、微调、蒸馏、Agentic RL、图检索、本地推理优化、Kubernetes 和复杂分布式调度，在主线形成基础后按需求学习。主线会讲如何判断是否需要这些方案，不把算法训练作为前置门槛。
