# 教学与知识维护方式

## 你的学习起点

Python 按初学者讲解，Java Web 经验用于建立联系。不能因为你会 Java，就省略 Python 的运行方式、引用、数据结构、异常、模块和异步机制。

## 每课的固定结构

1. **业务场景**：用主项目中的具体问题解释为什么要学。
2. **学习目标**：本课结束后能完成什么，前置知识是什么。
3. **概念讲解**：先提出本课具体困惑，用小例子推导规则，再给概念命名。
4. **操作演示**：文件位置、完整命令和预期结果。
5. **代码解释**：用具体输入逐步追踪名字绑定、状态或消息变化，说明分支为什么发生。
6. **常见错误**：症状、原因、检查步骤和修复方式。
7. **独立练习**：与示例相关，但需要迁移，不照抄完整答案。
8. **验收与回顾**：检查解释、修改、排错和验证能力。

讲义采用案例驱动与讲练结合的方法。进一步参考[Composing Programs：程序的元素](https://composingprograms.com/pages/12-elements-of-programming.html)、[可变数据](https://composingprograms.com/pages/24-mutable-data.html)和[CS61A控制与环境图讨论](https://cs61a.org/fa26/discussions/disc01/)：从小例子建立执行模型，先预测、再追踪、最后迁移。项目案例、中文解释和练习自行编写，不翻译搬运教材，也不照搬其课程进度。

## 讲义必须能够独立读懂

不能用“一句定义＋用途清单”替代讲解。读者在首次看到一个概念时，需要知道它解决什么问题、代码在哪里用到它、执行时具体发生什么，以及最容易与什么混淆。

以阶段02为例，先给一张工单说明字典，再组织成列表，逐个计算条件，画出每轮累计结果；理解这些以后，才讨论别名与浅复制。直接把“变量名绑定对象，赋值不是复制”放在开头，只能作为复习结论，不能承担初次教学。

每课的内容应满足以下标准：

- 前置知识必须真实：阶段02不假设会函数；练习需要新语法时，先提供与答案不同的小例子作过渡。
- 新语法就地解释：说明符号、输入、执行时机和返回结果，不把解释全部堆在文末词汇表。
- 正常过程可追踪：给具体输入和中间状态，不能只说“处理数据，返回结果”。
- 失败过程有原因：至少说明一个反例在哪一步被拒绝、哪些状态保持不变，不能只罗列异常名称。
- 预测题有推导：答案可折叠，先让学员判断，再解释为什么；不能把独立作业的完整答案提前写出来。
- Java对照说明差异：例如Python装饰器会替换函数对象，不能只写“类似Java注解”。
- 讲义与复习分工：README承担完整教学，knowledge用问题、反例和边界帮助检索，不再重复一份同样稀薄的名词清单。

采用这些标准不意味着每课都要同样长。阶段01保留已足够清楚的操作讲解，新增执行追踪；复杂课程则必须花足篇幅解释状态、权限、失败和恢复。不要用重复免责声明、通用验收口号或增加小标题凑篇幅。

## 代码怎样讲

- 新语法先用直白版本解释，再展示更简洁的写法。
- 不为了展示高级语法，在入门案例加入不必要的类、装饰器或抽象。
- 注释说明目的、输入、输出、关键状态和失败路径。
- 对复杂逻辑，讲义配执行过程；注释与代码共同维护。
- 所有代码文件，包括练习和答案，都有中文说明。
- 参考答案只作为对照，不代替你的独立实现。

## 怎样判断掌握

每课代码练习先运行[自动校验命令](exercise-checks.md)，自动收集检查结果和更新练习列；无需手动填写命令、输出和提交表。概念解释或真实集成仍需对应证据，可在对话中补充；不得把自动测试通过直接记为完整能力通过。

| 能力 | 需要的依据 |
| --- | --- |
| 能解释 | 用自己的话说明概念和执行过程 |
| 能修改 | 独立完成一个变化后的需求 |
| 能排错 | 根据命令、错误和状态定位问题 |
| 能验证 | 用运行结果或测试判断是否满足要求 |

能复制运行是起点。课程已经写好、示例已经通过验证，都不能证明你掌握了。

## 小练习与连续项目

每课小练习只验证一个概念或局部接口，学员应能自行写出输入、预期状态和失败路径。五个[主项目里程碑](milestones.md)逐步集成多个课程成果，检查既有接口、持久状态、权限和旧行为是否一起工作；小练习通过不代表里程碑完成，里程碑也不能替代单课概念解释。

## 贯穿项目的评估、安全和可观察性

- 阶段07开始把成功标准写成固定案例；阶段08保存开发集和保留验收集，真实调用要单列质量、延迟与用量。
- 阶段13开始记录决策、工具调用、工具观测和停止原因；阶段14—16继续关联审批与业务结果。
- 阶段17把文档中的恶意指令作为不可信输入测试；知识内容不能授予工具权限。
- 第一次增加写工具时，就验证服务端权限、审批绑定、参数变化、重复执行和结果不确定；阶段12/16/43进一步讲幂等与恢复。
- 阶段44—48系统深化评估、轨迹、安全与租户隔离。这些不是从零开始，而是把早期习惯扩展成发布和运行治理。

## 知识文档怎样维护

`knowledge.md` 是一个持续更新的知识手册，每个条目记录：概念、用途、最小例子、Java 对照、易错点、课程链接和来源。

课堂中的问题与作业反馈，确认原因后再写入相关条目。没有发生的错误不伪造为你的个人问题。全部56阶段资料已预先交付，但未学习或未验收的内容不能写成已掌握知识。

## 进度怎样维护

- 材料状态：未制作 / 已准备 / 已修订。
- 练习状态：未提交 / 待修改 / 代码校验通过 / 代码或规则已变化，待重验。自动校验只更新练习状态；额外项目成果单独验收。
- 能力状态：待验收 / 部分掌握 / 已通过。

只有你提交操作结果、解释或代码，并经检查后，才更新能力状态。阶段尚未通过时，可以补充练习，不按日期强制推进。

## 技术与资料选择

初期优先 Python 标准库。模型 SDK、框架与协议在使用时核查官方文档与版本；每次新增依赖说明用途。开源项目用于理解机制与设计取舍，不将照搬项目作为学习目标。
